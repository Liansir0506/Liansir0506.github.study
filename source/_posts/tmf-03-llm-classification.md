> **一句话概括**：把分类任务写成 Prompt 交给大模型——零训练、改需求只需改一句话，但成本和延迟是硬伤。
> **这篇有多重要**：🔥 —— 第四种方案，也是当下最常被问的："什么时候用大模型、什么时候微调？"
> **前置知识**：pe-01 的 Few-shot、pe-02 的结构化输出
> **对应素材**：`tmf/01课件/07-markdown/day04_LLM的提示词工程.md`

## 一、初识：为什么还要第四种方案

前三方案（RF / fasttext / BERT）都要**训练**：要标注数据、要调参、要重训。

但现实里经常遇到：

| 场景 | 问题 |
|---|---|
| 类别刚定，标注数据为 0 | 训练不了 |
| 类别经常变（业务调整） | 每次重训成本高 |
| 数据量小（几百条） | 微调容易过拟合 |
| 需求是"先看看效果" | 训练周期太长 |

**LLM + Prompt** 的方案：**不训练，直接用**。

## 二、运用：Zero-shot 分类

```python
import openai

client = openai.OpenAI(base_url="https://api.deepseek.com/v1")

CATEGORIES = ["历史", "军事", "体育", "旅行", "娱乐", "美妆"]

def classify(text: str) -> str:
    prompt = f"""你是一个新闻分类器。请把下面的文本分类到以下类别之一：
{", ".join(CATEGORIES)}

要求：
1. 只输出类别名称，不要输出其他内容
2. 如果无法判断，输出"其他"

文本：{text}"""
    res = client.chat.completions.create(
        model="deepseek-chat",
        messages=[{"role": "user", "content": prompt}],
        temperature=0,          # 分类任务要稳定
    )
    return res.choices[0].message.content.strip()
```

### 2.1 提升效果：Few-shot

给几个示例，模型更容易对齐你的分类标准：

```python
prompt = f"""你是一个新闻分类器，按以下示例的风格分类。

示例1：
文本：二战期间某战役的战术分析
类别：军事

示例2：
文本：新款面霜的成分与使用方法
类别：美妆

现在请分类：
文本：{text}
类别："""
```

> 📌 Few-shot 的关键：**示例要覆盖容易混淆的边界**（比如"历史"和"军事"的区分）。

### 2.2 结构化输出（批量场景必备）

如果一次要分很多条，用 JSON 约束：

```python
import json

prompt = f"""对以下文本分类，严格输出 JSON：
{{"label": "类别名", "confidence": 0.0~1.0, "reason": "简要理由"}}

类别：{", ".join(CATEGORIES)}
文本：{text}"""

data = json.loads(...)   # 或 with_structured_output
```

## 三、初识：四种方案的终极对比（面试核心表）

| 维度 | 随机森林 | fasttext | **BERT 微调** | **LLM 提示词** |
|---|---|---|---|---|
| **需要标注数据** | 多 | 多 | 中（可少） | **几乎不要**（few-shot 即可） |
| **需要训练** | 是 | 是 | 是 | **否** |
| **效果** | 基线 | 中上 | **高** | 中高（任务相关） |
| **推理速度** | 快 | **极快** | 慢 | 最慢（网络+生成） |
| **单次成本** | 极低 | 极低 | 低 | **高（按 token）** |
| **批量成本** | 低 | 低 | 低 | **很高** |
| **类别变更** | 重训 | 重训 | 重训 | **改 Prompt** |
| **可控性** | 高 | 高 | 高 | 中（可能不按格式输出） |

### 3.1 选型决策树（可以直接背）

```text
有大量标注数据 + 高并发 + 成本敏感？
    → fasttext（首选）或 BERT 微调（要效果）

数据少（< 1000 条）+ 类别稳定？
    → BERT 微调（少量数据也能微调）或 few-shot LLM

类别经常变 / 需求还在探索？
    → LLM + Prompt（改一句就生效）

追求极致效果且不计成本？
    → LLM（或 微调 + LLM 兜底难样本）

离线批量、千万级？
    → fasttext / BERT（LLM 成本不可接受）
```

> 🔥 面试答法："**高频、量大、成本敏感 → 小模型；数据少、类别常变、要求快速上线 → 大模型。** 两者还可以组合：小模型处理常规，难样本丢给 LLM 兜底。"

## 四、初识：LLM 分类的三个坑

| 坑 | 现象 | 解决 |
|---|---|---|
| **不按格式输出** | 返回"这段文本属于军事类"而不是"军事" | 强约束 + few-shot 示例 + 结构化输出 |
| **类别幻觉** | 输出一个不存在的类别 | 明确候选列表 + 输出后校验映射 |
| **批量成本爆炸** | 100 万条 × 每次 500 token | 小模型预筛 + LLM 只处理难样本 |

### 4.1 工程优化：小模型 + LLM 兜底

```text
全部样本 → fasttext 快速分类
   ├─ 置信度 > 0.9 → 直接采用（80% 样本）
   └─ 置信度 ≤ 0.9 → 交给 LLM 判断（20% 样本）
```

成本降到 1/5，效果接近纯 LLM——**这是企业里最常用的组合拳**。

## 五、总结

### 5.1 要点回顾

1. LLM 分类：**不训练、改 Prompt 即生效**，适合数据少/类别常变/快速验证
2. 两个关键技巧：**Few-shot 示例**（对齐标准）+ **结构化输出**（可解析）
3. 四种方案选择：看**数据量、并发量、成本、类别稳定性、效果要求**
4. 三个坑：格式失控、类别幻觉、批量成本
5. **最优解常是组合**：小模型预筛 + LLM 兜底难样本

### 5.2 自测清单

<details>
<summary>Q1：什么时候用 LLM 分类比微调更合适？</summary>

标注数据少、类别经常变、要快速验证、量不大——这些场景微调的投入产出比很差，LLM 改 Prompt 即可。
</details>

<details>
<summary>Q2：LLM 分类怎么做才稳定？</summary>

temperature=0、明确候选类别、给 few-shot 示例、结构化输出（JSON schema）、输出后校验映射。
</details>

<details>
<summary>Q3：大批量分类怎么控成本？</summary>

小模型先分（高置信度直接采用），只把难样本交给 LLM；或用蒸馏把 LLM 的标注结果训成小模型。
</details>

### 5.3 面试视角（🔥）

| 面试问法 | 答题要点 |
|---|---|
| LLM 做分类的方案？ | Prompt（zero/few-shot）+ 结构化输出 + 后校验 |
| 和微调怎么选？ | 数据/并发/成本/类别稳定性四要素；量大用小模型，变动用 LLM |
| 怎么降低 LLM 成本？ | 小模型预筛 + 难样本兜底；缓存；蒸馏 |
| LLM 分类的稳定性怎么保证？ | 低温、格式约束、few-shot、输出校验、兜底策略 |
