## 一、初识：Dify 是什么

**Dify** 是一款**开源**的大语言模型（LLM）应用开发平台，核心卖点是"**BaaS（Backend as Service，后端即服务）**"：

> 把搭建 AI 应用需要的后端能力——模型接入、Prompt 编排、RAG 引擎、Agent 框架、流程编排——全部内置好，你只关注业务逻辑。

它内置了什么：

| 能力 | 说明 |
|---|---|
| **多模型支持** | 数百个模型（OpenAI、通义、DeepSeek、本地 ollama…） |
| **Prompt 编排** | 可视化编辑器 + 变量 + 调试 |
| **RAG 引擎** | 知识库、分段、检索、rerank |
| **Agent 框架** | 工具调用、ReAct |
| **流程编排** | 工作流 / 对话流（可视化 DAG） |
| **API 与嵌入** | 每个应用都能生成 API，或嵌到网页 |

### 1.1 安装方式：私有化部署

Dify 可以 Docker 一键部署在自己机器/服务器上：

```text
① 安装 WSL（Windows 下跑 Linux 环境）
   wsl --install
② 安装 Docker Desktop（并配置国内镜像源加速）
③ 下载 dify 源码 → 进入 docker 目录 → 复制 .env.example 为 .env
④ docker compose up -d
⑤ 浏览器访问 http://localhost  完成初始化（设置管理员账号）
```

> 💡 私有化部署的意义：**数据不出内网、可以接本地模型、可以访问公司内网数据库**——这三点是 SaaS 平台（Coze 在线版）做不到的。

## 二、初识：Dify vs Coze（面试高频）

两个平台概念几乎一一对应（Bot≈应用、插件≈工具、工作流≈工作流、知识库≈知识库），但**定位完全不同**：

| 维度 | **Coze（在线版）** | **Dify（可私有化）** |
|---|---|---|
| **开源/部署** | SaaS，用官方云 | **开源，可 Docker 私有部署** |
| **上手速度** | 更快（模板多、生态全） | 稍慢（要装环境） |
| **模型接入** | 平台提供的模型 | **任意模型，含本地 ollama** |
| **数据安全** | 数据在第三方云 | **数据在你自己服务器** |
| **访问内网/本地库** | ❌ 不行 | ✅ 可以（同内网） |
| **网页嵌入** | 受限 | ✅ 支持 iframe/API 嵌入自己的网站 |
| **插件生态** | 丰富（官方+第三方） | 较少，很多要自己写 |
| **发布渠道** | 飞书/微信/抖音等渠道丰富 | 以 API/网页嵌入为主 |
| **适合场景** | 快速验证、C 端渠道分发、内部工具 | **企业私有化、数据敏感、要和自有系统集成** |

### 2.1 怎么选（一句话总结）

> **要"快"和"渠道"，用 Coze；要"数据可控"和"系统集成"，用 Dify。**

再结合前面 AI 面试助手项目的选型逻辑（coze-05）：
- 项目初期验证 → Coze（快）
- 数据在本地、要嵌网站 → Dify（法律助手就是这么选的，见 dify-03）

## 三、初识：Dify 的五种应用类型

Dify 创建应用时先选类型，这决定了它的能力边界：

| 类型 | 是什么 | 适合 |
|---|---|---|
| **聊天助手（Chatbot）** | 对话式应用 | 客服、问答助手 |
| **文本生成** | 单次输入输出 | 写作、翻译、摘要 |
| **Agent** | 带工具调用、自主规划的对话 | 多步任务、查数据 |
| **工作流（Workflow）** | 单向流程图（输入→处理→输出） | 批量处理、内容流水线 |
| **对话流（Chatflow）** | 带对话状态的工作流 | **多轮对话 + 分支逻辑**（法律助手用的就是它） |

> 📌 面试点：**Workflow 和 Chatflow 的区别**——Workflow 是"一次性任务"（给输入、出结果），Chatflow 有"对话记忆"，能多轮交互并记住上下文。

## 四、总结

### 4.1 要点回顾

1. Dify = **开源、可私有化部署**的 LLM 应用平台（BaaS 理念）
2. 内置：多模型、Prompt 编排、RAG 引擎、Agent、流程编排、API/嵌入
3. **Coze vs Dify**：快/渠道 vs 数据可控/系统集成；SaaS vs 开源自部署
4. 五种应用类型：聊天助手、文本生成、Agent、**工作流、对话流**（对话流 = 带记忆的工作流）
5. 私有化部署的三大价值：**数据不出内网、接本地模型、访问内网数据库**

### 4.2 自测清单

<details>
<summary>Q1：Dify 和 Coze 最本质的区别？</summary>

Dify 开源、可私有化部署，模型/数据/数据库都能自己掌控；Coze 是 SaaS，生态和渠道更丰富、上手更快，但数据在第三方云、不能访问本地资源。
</details>

<details>
<summary>Q2：什么场景必须用 Dify 而不是 Coze？</summary>

数据不能出内网、需要接入公司本地数据库、需要把机器人嵌入自己的网站、需要使用本地模型。
</details>

<details>
<summary>Q3：Workflow 和 Chatflow 的区别？</summary>

Workflow 是单次输入输出的流程（无对话状态）；Chatflow 带对话记忆，适合多轮交互和基于上下文的复杂分支。
</details>

### 4.3 面试视角（📌）

| 面试问法 | 答题要点 |
|---|---|
| Coze 和 Dify 怎么选？ | 快/渠道选 Coze；数据可控/私有化/系统集成选 Dify |
| Dify 的核心能力？ | 多模型接入、Prompt 编排、RAG、Agent、工作流/对话流、API 嵌入 |
| 私有化部署的价值？ | 数据安全合规、本地模型、访问内网数据、无 vendor lock-in |
| Dify 的局限？ | 插件生态少于 Coze、部分高级定制仍要写代码 |
