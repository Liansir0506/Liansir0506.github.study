> **一句话概括**：面试不是"背答案"，而是用结构化方式证明"你做过、你懂、你能扛事"——这篇给的是结构。
> **这篇有多重要**：🔥🔥 —— 技术都会了，讲不出来等于没有。这套方法对每一场面试都直接可用。
> **前置知识**：无（但建议先把前面所有模块过一遍，才有东西可讲）
> **对应素材**：`tmf/01课件/07-markdown/day07_模拟面试.md`、`day06_项目答辩.md`

## 一、初识：简历要写什么

### 1.1 必含项

| 板块 | 内容 |
|---|---|
| 基本信息 | 姓名、电话、邮箱、城市、求职方向 |
| 教育背景 | 学校、专业、学历、时间 |
| **技能清单** | **只写熟练且能讲清原理的技术** |
| **项目经历** | 2~4 个，按"背景-职责-方案-结果" |
| 工作经历（如有） | 公司、岗位、时间、核心产出 |
| 个人亮点 | 证书/开源/竞赛/高价值成果（可选） |

### 1.2 项目描述四段式（核心）

```text
① 项目背景：解决什么业务问题
② 个人职责：我负责哪些核心模块（不是"参与了"）
③ 技术方案：用了什么、为什么这么选
④ 结果指标：ACC/F1/延迟/成本等数据
```

❌ 差：`参与开发了一个文本分类系统，使用 BERT 模型。`
✅ 好：`负责新闻文本多分类模块（6 类），对比 TF-IDF+RF / fasttext / BERT 微调 / LLM 四种方案，最终选定 BERT 微调（macro-F1 0.89，较基线 +12%），并通过量化把推理延迟从 120ms 降到 35ms。`

### 1.3 三条写作规则

| 规则 | 说明 |
|---|---|
| **一条一句重点** | 少空话，多结果 |
| **尽量带数字** | "ACC 92%→95%"、"延迟降低 3 倍" |
| **技能与项目一一对应** | 别写"会很多、讲不出" |

> 🔥 面试官只看两件事：**你解决过什么问题、有什么证据**。所有空话都可以删。

## 二、运用：自我介绍（30~60 秒）

### 2.1 四段结构

```text
① 身份与年限：我是谁，工作/学习多久
② 技术栈：常用框架与方向
③ 项目经验：做过哪些类型项目
④ 匹配度：为什么适合这个岗位
```

### 2.2 模板（可直接改）

> 面试官您好，我是 XXX，有 X 年 AI/NLP 相关经验。常用技术包括 Python、PyTorch、机器学习/深度学习、LLM 应用开发。做过【行业】的【项目类型】项目，主要负责【核心模块】。我了解贵司岗位的工作内容，与我的经验匹配度较高，希望有机会在贵司持续产出价值。

> ⚠️ 控制在一分钟内，别背诵感太重；**最后一句落到"匹配"**，把话题引向岗位。

## 三、运用：项目怎么讲——8 步法（核心）

### 3.1 八个步骤

| # | 说什么 | 要点 |
|---|---|---|
| 1 | **这是什么项目**（1 句话） | 让面试官快速定位 |
| 2 | **为什么做**（业务背景） | 体现业务理解 |
| 3 | **你负责什么**（核心职责） | 明确边界，别贪功 |
| 4 | **技术怎么选**（方案对比） | **体现选型能力**（最关键） |
| 5 | **怎么落地**（关键实现） | 讲 1~2 个技术细节 |
| 6 | **遇到什么问题**（bug/瓶颈） | 体现真实经历 |
| 7 | **怎么解决**（排查与优化） | 体现解决问题能力 |
| 8 | **最终结果与收获**（指标+复盘） | 用数据收尾 |

### 3.2 讲解的三个"必须有"

| 必须有 | 为什么 |
|---|---|
| **有指标** | 准确率、F1、延迟、成本——没数据等于没做过 |
| **有取舍** | 为什么不用方案 B——证明你想过 |
| **有问题** | 至少准备 2~3 个真实问题及解法——证明你踩过坑 |

### 3.3 项目回答模板（可套用）

> 这个项目是【类型】项目，目标是解决【业务问题】。我主要负责【模块 A/B】。方案上我们采用【技术 1】实现【能力】，并通过【技术 2】优化【问题】。上线前遇到【问题】，根因是【原因】，最终通过【措施】解决。项目最终达到【指标结果】，我的收获是【经验沉淀】。

## 四、运用：问题回答框架

### 4.1 通用框架：结论 → 依据 → 结果

```text
结论：先给最终答案（一句话）
依据：给方法和原因（2~3 句）
结果：给数据或效果（1 句）
```

例：

- 问："你为什么不选 LLM 做分类？"
- 答："**因为成本和延迟不可接受**（结论）。我们每天几十万条文本，LLM 单条 0.003 元、延迟 800ms，成本是 fasttext 的百倍以上（依据）。最终用 fasttext + BERT 兜底难样本，延迟控制在 40ms 内、准确率只低 3 个点（结果）。"

### 4.2 四类问题清单（提前准备答案）

| 类别 | 常见问题 |
|---|---|
| **数据** | 训练/测试规模？如何标注？怎么保证质量？如何防泄漏？ |
| **模型与调优** | 为什么选这个模型？调了哪些超参？Bad case 怎么分析处理？ |
| **工程与部署** | 服务怎么部署？线上 QPS/延迟？故障怎么定位与回滚？ |
| **行为问题** | 离职原因（客观正向）、职业规划（1 年夯实/3 年独立负责）、优缺点（能力+例子 / 改进点+措施）、期望薪资（先区间再依据） |

### 4.3 反问面试官（体现主动性）

- "这个岗位或部门当前最核心的项目是什么？"
- "入职后 1~3 个月的考核重点是什么？"

> 💡 反问别问"加班多吗""福利如何"——问业务和成长。

## 五、初识：面试前清单（照着准备）

- [ ] 自我介绍（30~60 秒，练到自然）
- [ ] 每个项目都有"背景-职责-方案-结果"四段
- [ ] 每个项目准备 **3 个技术追问**及回答
- [ ] 准备 **2 个非技术问题**（离职原因、职业规划）
- [ ] 准备 **2 个高质量反问**
- [ ] 简历上的每个技术，都能讲清原理（写了的必须会）

## 六、总结

### 6.1 要点回顾

1. 简历：**四段式项目描述**（背景-职责-方案-结果），带数字、少空话
2. 自我介绍：身份 → 技术栈 → 项目 → **匹配度**（30~60 秒）
3. **项目 8 步法**：是什么 → 为什么 → 我负责 → 怎么选 → 怎么落地 → 什么问题 → 怎么解决 → 结果收获
4. 讲解三必须：**有指标、有取舍、有问题**
5. 回答框架：**结论 → 依据 → 结果**；反问问业务与成长

### 6.2 自测清单

<details>
<summary>Q1：项目描述的四段式？</summary>

背景（业务问题）、职责（我负责的模块）、方案（技术与选型理由）、结果（指标数据）。
</details>

<details>
<summary>Q2：项目 8 步法是哪八步？</summary>

是什么、为什么做、我负责什么、技术怎么选、怎么落地、遇到什么问题、怎么解决、结果与收获。
</details>

<details>
<summary>Q3：为什么"有取舍"很重要？</summary>

能说出"为什么不用方案 B"证明你真的思考过技术选型，而不是"别人让用什么就用什么"——这是中级和高级的分水岭。
</details>

### 6.3 面试视角（🔥🔥 实战）

| 场景 | 要点 |
|---|---|
| 自我介绍 | 30~60 秒四段，落点是匹配度 |
| 项目讲解 | 8 步法，控制在 3~5 分钟，留出追问空间 |
| 技术追问 | 结论-依据-结果；不会的坦诚说"这块我没深入，我的理解是……" |
| 行为问题 | 客观正向、不抱怨前公司 |
| 反问 | 问核心项目与考核重点 |
