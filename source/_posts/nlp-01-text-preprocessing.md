## 一、初识：中文为什么必须分词

英文句子天然有空格：

```text
I love natural language processing
```

按空格切开就是词。但中文呢？

```text
结婚的和尚未结婚的
```

机器怎么知道该切成"结婚 / 的 / 和 / 尚未 / 结婚 / 的"，而不是"结婚 / 的 / 和尚 / 未 / 结婚 / 的"？

**这就是分词（Word Segmentation）要解决的问题**：在没有空格的情况下，找出词的边界。

> 分错了词，后面的词性、向量、模型全都会跟着错——所以它是中文 NLP 的地基。

## 二、运用：jieba 三种分词模式

jieba 是中文分词最常用的工具：

```bash
pip install jieba
```

三种模式，各有用途：

| 模式 | 方法 | 特点 | 用在哪 |
|---|---|---|---|
| **精准模式** | `jieba.cut(s)` | 保证语义完整 | **文本分析、分类**（最常用） |
| 全模式 | `jieba.cut(s, cut_all=True)` | 尽可能多切，词全但可能冗余 | 关键词抽取、粗筛 |
| 搜索模式 | `jieba.cut_for_search(s)` | 长词再切成短词 | 搜索引擎、召回 |

```python
import jieba

sentence = "烦恼即是菩提，我暂且不提"

# 精准模式：语义完整（推荐默认用这个）
print(list(jieba.cut(sentence)))
# ['烦恼', '即是', '菩提', '，', '我', '暂且', '不提']

# 全模式：尽可能切
print(list(jieba.cut(sentence, cut_all=True)))
# ['烦恼', '即是', '菩提', '，', '我', '暂且', '不提', ...]（更多碎片）

# 搜索模式：长词切短
print(list(jieba.cut_for_search(sentence)))

# 注意 cut 返回生成器，lcut 直接返回列表
print(jieba.lcut(sentence))
```

> 📌 `cut` 是生成器（省内存，适合大文件流式处理），`lcut` 返回列表（方便直接用）。

### 2.1 自定义词典：专业术语切不对怎么办

jieba 的通用词典不认识"专业名词"（比如"投满分""RAG 检索增强"）。两种解决：

```python
# 方法一：加载自定义词典文件
# userdict.txt 格式：词  词频  词性（每行一个）
# 投满分 100 n
# 检索增强 100 n
jieba.load_userdict("userdict.txt")

# 方法二：动态添加
jieba.add_word("检索增强生成")

print(jieba.lcut("我在做投满分的检索增强生成项目"))
```

> 💡 词频（第二列）的作用：**如果这个词和别的词有包含关系，词频要设大一些才切得对**。

## 三、运用：词性标注与命名实体

### 3.1 词性标注（POS）

```python
import jieba.posseg as pseg

result = pseg.cut("我爱北京天安门")
for word, flag in result:
    print(word, flag)

# 我 r（代词）
# 爱 v（动词）
# 北京 ns（地名）
# 天安门 ns
```

常见词性：`n` 名词、`v` 动词、`a` 形容词、`d` 副词、`ns` 地名、`nr` 人名。

> 词性有什么用？——做特征过滤（只保留名词做关键词）、句法分析、信息抽取。

### 3.2 命名实体识别（NER）

**NER（Named Entity Recognition）**：从文本里识别出**人名、地名、机构名、时间、金额**等有特定意义的实体。

```text
"张三 2026 年入职 腾讯 ，月薪 3 万"
  ↓ NER
  [人名: 张三] [时间: 2026 年] [机构: 腾讯] [金额: 3 万]
```

jieba 自带简易 NER（靠词性：`nr` 人名、`ns` 地名），但工业级 NER 用深度学习模型（BiLSTM-CRF、BERT，nlp-05 会用 transformers 跑一个真正的 NER）。

## 四、运用：one-hot——把词变成数字的第一步

分词完，词还是文字。模型只认数字，所以要做**向量化**。

### 4.1 one-hot 怎么做（手搓版）

```python
words = ["关羽", "张飞", "赵云", "马超"]

# 1. 建词表：词 → 索引
word_index = {w: i for i, w in enumerate(words)}
print(word_index)   # {'关羽': 0, '张飞': 1, '赵云': 2, '马超': 3}

# 2. 每个词变成一个"只有自己位置是 1"的向量
for w in words:
    vec = [0] * len(word_index)
    vec[word_index[w]] = 1
    print(w, vec)

# 关羽 [1, 0, 0, 0]
# 张飞 [0, 1, 0, 0]
# 赵云 [0, 0, 1, 0]
# 马超 [0, 0, 0, 1]
```

也可以用 sklearn 的 `OneHotEncoder` 或 PyTorch 的 `F.one_hot` 一行搞定。

### 4.2 one-hot 的两个致命缺点

| 缺点 | 说明 |
|---|---|
| **维度爆炸** | 词表 10 万个词 → 每个词是 10 万维向量，99.99% 是 0（极端稀疏） |
| **没有语义** | "猫"和"狗"的 one-hot 向量距离，跟"猫"和"汽车"一样远——完全看不出相关性 |

> 这两条正是**词向量**要解决的问题。下一篇：把 10 万维的稀疏向量，压缩成 100 维的稠密向量，而且语义相近的词距离也近。

## 五、总结

### 5.1 要点回顾

1. 中文没有空格 → 必须分词；分词是中文 NLP 的地基
2. jieba 三种模式：**精准（默认）/ 全模式 / 搜索模式**；`cut` 生成器、`lcut` 列表
3. 专业术语切不对 → **自定义词典**（词 / 词频 / 词性）
4. 词性标注 `posseg`：给每个词打上 n/v/a 等标签；简易 NER 靠词性识别人名地名
5. **one-hot** 把词变成 0/1 稀疏向量，但**维度爆炸 + 无语义** → 促使了词向量的诞生

### 5.2 自测清单

<details>
<summary>Q1：jieba 三种分词模式分别用在哪？</summary>

精准模式：文本分析/分类（默认）；全模式：关键词抽取等需要尽可能多切词的场景；搜索模式：搜索引擎召回（长词切短，提高匹配率）。
</details>

<details>
<summary>Q2：自定义词典的文件格式是什么？</summary>

每行一个词：`词 词频 词性`。词频用于处理包含关系时的切分优先级。
</details>

<details>
<summary>Q3：one-hot 有什么缺点？</summary>

维度随词表线性增长（稀疏、占内存）；任意两个词的向量距离相同，无法表达语义相似性。
</details>

<details>
<summary>Q4：cut 和 lcut 的区别？</summary>

cut 返回生成器，适合流式处理大数据；lcut 返回列表，方便直接使用。
</details>

### 5.3 面试视角（📌）

| 面试问法 | 答题要点 |
|---|---|
| 中文分词有哪些方法？ | 词典匹配（jieba）、统计模型（HMM/CRF）、深度学习（BiLSTM-CRF/BERT） |
| jieba 的原理？ | 基于词典构造 DAG（有向无环图），用动态规划找最大概率路径；未登录词用 HMM |
| 分词对下游任务的影响？ | 分词错误会级联传播到词性、向量、模型效果；可用子词（BPE）缓解 |
| one-hot 和 embedding 的区别？ | 稀疏高维 vs 稠密低维；无语义 vs 有语义 |

### 5.4 下一步

one-hot 之后，是 NLP 最重要的一次升级：**词向量（word2vec）**——把"苹果"和"水果"放到向量空间里相近的位置。
