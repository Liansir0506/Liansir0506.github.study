## 一、初识：为什么检索方式不止一种

用户问："劳动合同到期不续签，公司要赔钱吗？"

知识库里有一堆文档，怎么找相关的？

| 思路 | 做法 | 擅长 |
|---|---|---|
| **关键词匹配** | 找含"劳动合同""到期""赔偿"的文档 | 精确词、术语、编号 |
| **语义相似** | 理解"要不要赔钱"≈"经济补偿"，找意思相近的 | 同义表达、口语化提问 |
| **两者都要** | 各取所长，结果合并重排 | 真实业务 |

这就是三种检索方式：**全文检索、语义检索、混合检索**。

## 二、初识：全文检索——关键词 + 倒排索引

### 2.1 倒排索引是什么

想象一本书的索引页："机器学习 → 第 3、17、42 页"。

倒排索引就是这个东西：**不是"文档→包含哪些词"，而是"词→出现在哪些文档"**。

```text
正向索引（原始文档）：
文档1: "劳动合同到期不续签需要赔偿"
文档2: "试用期辞退的补偿标准"

倒排索引：
劳动合同 → [文档1]
到期     → [文档1]
赔偿     → [文档1]
试用期   → [文档2]
补偿     → [文档2]
```

建立索引的过程：**分词 → 记录每个词出现在哪些文档/位置 → 排序**。

查询时：把问题也分词 → 在索引里一查就知道哪些文档相关 → **不用扫描全部文档**，速度极快。

### 2.2 相关性排序：BM25

找到含关键词的文档后，还要排序——哪个更相关？

**BM25** 是经典算法，核心思想：

| 因素 | 影响 |
|---|---|
| 词在文档中出现次数（TF） | 出现越多越相关（但有饱和上限） |
| 词在整个语料的稀有度（IDF） | "劳动合同"这种稀有词比"的"权重高得多 |
| 文档长度 | 长文档中的命中要打折（避免长文档占便宜） |

> 📌 面试答法："全文检索用倒排索引实现'词→文档'的快速查找，用 BM25 做相关性排序。"

### 2.3 全文检索的局限

| 问题 | 例子 |
|---|---|
| **语义鸿沟** | 用户问"要赔钱吗"，文档写"应支付经济补偿"——关键词对不上 |
| **同义词** | "辞退/解雇/开除"——词不同，意思一样 |
| 分词质量 | 中文分词出错，检索就废了 |

→ 这就是语义检索要解决的问题。

## 三、初识：语义检索——向量 + 相似度

### 3.1 原理

1. 离线：把每个文档片段用 embedding 模型转成向量，存进向量库
2. 在线：问题也转成向量
3. 计算余弦相似度，找最接近的 top-k 片段

> 这就是 nlp-02 学的"语义相近 = 向量距离近"，只是对象从"词"变成"文档片段"。

### 3.2 优势与局限

| 优势 | 局限 |
|---|---|
| 理解同义/近义表达 | 精确匹配差（专有名词、编号、法条号可能找不准） |
| 跨语言、口语化提问 | 依赖 embedding 模型质量 |
| 不需要分词 | 训练/推理成本高于倒排索引 |

## 四、初识：混合检索——成年人全都要

**混合检索（Hybrid Search）**：同时跑全文检索和语义检索，把两路结果合并后再排序。

两种融合策略：

| 策略 | 做法 | 特点 |
|---|---|---|
| **权重融合** | 给两路结果各设权重（如关键词 0.3 + 语义 0.7），加权求和排序 | 简单，权重靠调 |
| **Rerank（重排）** | 用专门的 rerank 模型（如 bge-reranker）对候选结果统一打分排序 | 效果最好，成本略高 |

### 4.1 Rerank 是什么（面试常问）

普通语义检索用的是"双塔"结构：问题和文档**各自独立编码**再算相似度——快，但精度有限。

**Rerank 模型**用的是"交叉编码"：把**问题和文档拼在一起**送进模型，直接判断相关性——**准，但慢**。

所以标准做法是两阶段：

```text
① 粗排（召回）：向量检索快速取 top 50
② 精排（rerank）：用 rerank 模型对这 50 条重排，取 top 5
```

> 🔥 这个"召回 → 重排"的两阶段结构，是所有工业级检索系统的标配。记住这个词组合：**召回率看粗排，准确率看重排**。

## 五、初识：Dify 知识库怎么建

### 5.1 数据源与格式

支持 TXT、Markdown、PDF、HTML、XLSX、DOCX、CSV 等——上传后自动解析。

### 5.2 两种分段模式（关键）

| 模式 | 做法 | 适合 |
|---|---|---|
| **通用模式** | 按固定规则（字数/分隔符）切块 | 结构简单的文档 |
| **父子模式** ⭐ | 切成"父块（大段）+ 子块（小段）"：**用子块检索，把父块喂给模型** | 需要上下文完整的场景 |

**父子模式的巧妙之处**：

- 子块小 → 检索精准（小片段更容易匹配问题）
- 父块大 → 喂给模型时上下文完整（不会因为切片太碎而丢失语义）

> 🔥 这是 RAG 工程里非常实用的技巧，面试聊"切片策略"时可以提。

### 5.3 检索参数

| 参数 | 作用 | 建议 |
|---|---|---|
| **检索模式** | 全文 / 语义 / 混合 | 生产环境优先混合 |
| **Top-K** | 召回几条 | 3~10；rerank 时粗排可以更大（20~50） |
| **相似度阈值** | 低于阈值不要 | 防"硬凑不相关内容" |
| **Rerank** | 开启重排 | 对精度要求高时开 |

## 六、总结

### 6.1 要点回顾

1. **全文检索**：关键词 + 倒排索引 + BM25 排序；精确但不懂同义
2. **语义检索**：embedding 向量 + 余弦相似度；懂语义但精确匹配弱
3. **混合检索**：两路合并，**权重融合**或 **rerank 重排**
4. **Rerank = 交叉编码**：问题+文档一起送模型打分，准但慢——所以"粗排召回 → rerank 精排"两阶段
5. Dify 知识库：多格式数据源、**通用/父子两种分段**、top-k / 阈值 / rerank 参数

### 6.2 自测清单

<details>
<summary>Q1：倒排索引是什么？为什么快？</summary>

"词 → 文档列表"的映射。查询时对问题分词后直接查表定位文档，不需要扫描全部文档，所以快。
</details>

<details>
<summary>Q2：全文检索和语义检索各有什么短板？</summary>

全文：不懂同义词和语义（"赔钱"对不上"经济补偿"）；语义：精确匹配弱（法条编号、专有名词可能找不准）。
</details>

<details>
<summary>Q3：Rerank 和向量检索的区别？</summary>

向量检索是双塔（分别编码再算相似度）——快但粗；rerank 是交叉编码（问题和文档一起编码）——准但慢，用于精排。
</details>

<details>
<summary>Q4：父子分段模式解决什么问题？</summary>

检索用小片段保证精准，喂给模型用大片段保证上下文完整，兼顾召回准确率和生成质量。
</details>

### 6.3 面试视角（🔥🔥）

| 面试问法 | 答题要点 |
|---|---|
| RAG 的检索有哪些方式？ | 全文（倒排索引+BM25）/ 语义（向量）/ 混合（权重或 rerank） |
| 倒排索引的原理？ | 词→文档映射；分词建索引，查询查索引，BM25 排序 |
| 为什么需要 rerank？ | 双塔检索精度有限；交叉编码对候选重排可显著提升准确率 |
| 切片策略怎么设计？ | 按结构切、控制长度与重叠；父子分段兼顾精度与上下文 |
| 召回率低怎么优化？ | 换 embedding 模型、混合检索、查询改写、扩大 top-k、补数据 |
