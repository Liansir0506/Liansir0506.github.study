## 一、初识：项目背景——从真实痛点出发

**背景**：2025 年初 DeepSeek 带火 AI 赛道，某职业教育机构 AI 学科报名人数激增，教学能应付，但**就业环节效率撑不住了**。

四个具体痛点：

| 痛点 | 具体问题 |
|---|---|
| **简历修改** | 学生写简历水平参差、细节多，初版质量难把控 |
| **面试录音分析** | 一场面试 40 分钟；高峰期一个学生 3 场 = 2 小时录音，3 个学生就是 6 小时——**老师根本听不完** |
| **面试题背题** | 面试宝典体量太大，学生抓不住重点 |
| **模拟面试** | 练习次数不够，实际面试容易浪费机会 |

> 💡 面试聊项目时，**先说痛点再说方案**——这比直接讲技术更能体现"业务思维"。

## 二、初识：规划与取舍——为什么先不做模拟面试

理想情况四个痛点都要解决，但资源有限（1~2 个大模型工程师、3 个月），必须排序：

**一期做**：简历修改 + 面试录音分析 + 面试题生成 + 批处理

**模拟面试放二期**，原因：

| 原因 | 说明 |
|---|---|
| **实现难度高** | 要 ASR + TTS + 多轮追问 + 判断回答对错 + 控制面试节奏 |
| **紧迫性次之** | 大部分学生的问题是"知识没掌握"，不是"表达不好"——先解决面试题生成，能覆盖多数需求 |

> 🔥 这段是很好的面试素材：**"需求取舍"体现的是产品思维**——不是所有需求都要做，要看"投入产出比"。

**落地节奏**：2 周出 MVP（验证可行性）→ 2 个月功能完成 → 2.5 个月测试修复 → 3 个月小流量。

## 三、初识：业务流程与多 Agent 架构

统一入口 + 多子 Agent 分发（就是 coze-04 的主从模式）：

```text
学生 → 面试助手 Bot（父 Agent：识别意图）
          ├─ 上传简历 → 简历评估 Agent
          │      · 规则检查（格式/完整度）
          │      · 模板查重
          │      · 违禁词检测
          ├─ 上传录音 → 面试录音分析 Agent
          │      · ASR 转文字
          │      · 对照面试宝典判断回答准确性
          │      · 输出逐轮分析 + 原始文字稿
          └─ 要求出题 → 面试题生成 Agent
                 · 结合简历 + 真实面经 + 宝典
                 · 圈出重点和高频题（RAG）
```

两个工程细节值得注意：

1. **面试录音分析为什么要返回原始文字稿？**——老师可以对着文字快速核对，不用重听录音，效率翻倍
2. **面试题生成为什么要 RAG？**——基于简历（个人情况）+ 宝典（标准答案）+ 真实面经（高频题），三者结合才准

## 四、初识：技术选型——三套方案的对比（⭐ 面试可直接引用）

| 方案 | 优势 | 劣势 | 适用 |
|---|---|---|---|
| **Coze 在线版** | 低代码、快速实现需求 | 限制较多，难做定制化 | 快速验证、中小规模 |
| **Dify 本地版** | 低代码 + 能接本地模型和服务 | 本地版插件少，要自己造轮子 | 数据敏感、需本地部署 |
| **LangGraph 等代码框架** | 扩展性极强、支持高并发、复杂逻辑随便写 | 上手成本高、开发周期长 | 核心产品、规模化 |

**本项目的决策**：

> 一期用 **Coze 在线版**快速上线验证；如果有一定规模，再用 **LangGraph 重构**并集成进教学系统。

这个决策逻辑可以提炼成一句话：

> **先活下来，再优化。** 验证阶段拼的是"快"，规模化阶段拼的是"可控"。

## 七、总结

### 7.1 要点回顾

1. 项目从真实痛点出发：简历修改、录音分析、背题低效、模拟练习不足
2. **一期取舍**：砍掉模拟面试（难度高、紧迫性次之）——体现产品思维
3. 架构 = 统一入口 + 意图识别 + 多子 Agent（主从模式）
4. **技术选型**：Coze（快）/ Dify 本地（数据敏感）/ LangGraph（规模化）——一期用 Coze 验证，规模化再重构
5. 项目把所有知识串起来：Prompt + 多模态 + 循环 + 知识库 + Multi-Agent + 工作流

### 7.2 自测清单

<details>
<summary>Q1：这个项目为什么一期不做模拟面试？</summary>

实现难度高（ASR/TTS/多轮追问/评估），且紧迫性低于面试题生成；先解决多数学生的核心痛点，剩余放二期。
</details>

<details>
<summary>Q2：Coze、Dify、LangGraph 怎么选？</summary>

Coze：快速实现、限制多；Dify 本地：可接本地模型、插件少；LangGraph：扩展性最强、成本最高。看规模与定制需求。
</details>

<details>
<summary>Q3：面试录音分析为什么要切片循环？</summary>

40 分钟录音太长，一次性分析会超上下文、丢细节；ASR 转写后按对话轮次切片，逐轮分析再汇总更准。
</details>

<details>
<summary>Q4：如果重做这个项目，你会改什么？</summary>

可以先做评测集量化效果（评估准确率）、加缓存降成本、把关键 Agent 换成代码框架提高可控性、加监控和人工复核流程。
</details>

### 7.3 面试视角（📌 项目经验）

| 面试问法 | 答题要点 |
|---|---|
| 介绍一个你做过的 AI 项目 | 背景痛点 → 方案选型 → 架构（多 Agent）→ 难点与取舍 → 效果与改进 |
| 为什么用 Coze 而不是自己写？ | 验证期求快；规模化再迁 LangGraph；按人力/周期/定制需求权衡 |
| 多 Agent 怎么分工？ | 统一入口父 Agent 做意图识别，子 Agent 各管简历/录音/出题 |
| 项目难点？ | 长录音切片分析、RAG 出题准确性、成本与延迟控制 |
| 怎么评估项目效果？ | 简历评估采纳率、录音分析准确率（人工抽样）、题目命中率 |
