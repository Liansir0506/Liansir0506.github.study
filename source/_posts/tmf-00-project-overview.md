## 一、初识：业务背景

> 你入职了一家大模型公司，团队要做一个功能：**自动识别不同类别的文档，推送给感兴趣的部门/用户**。

对标字节跳动的两个产品：

| 产品 | 内容形态 | 分类的价值 |
|---|---|---|
| 抖音 | 短视频 | —— |
| **今日头条** | 短文本（新闻/资讯） | **先判断文本类别，再推荐给感兴趣的用户** |

用户兴趣差异很大：有人只看历史军事，有人只关注旅行美妆。

**如果系统能先判断一条文本属于哪个类别**，就能：

- 提升点击率（推得更准）
- 提升阅读时长
- 提升订阅与付费转化

你在团队中只负责**文本分类**这个子模块——就像给快递分拣：**先分对格子，才能"投满分"**。

## 二、初识：项目架构——为什么是四种方案

文本分类的方法太多，为什么选这几个？

> 答案：**选有代表性的、覆盖完整技术演进线的**——从简单到复杂、从手工到自动、从全量训练到微调到无需训练。

```text
手工特征 + 传统 ML（随机森林）
        ↓ 更强的文本表示
词向量 + 浅层网络（fasttext）
        ↓ 预训练 + 微调
预训练模型微调（BERT）
        ↓ 上下文学习，无需训练
大模型 + Prompt（DeepSeek）
        ↓ 部署优化
模型压缩（低秩分解）
```

| 方案 | 需要训练吗 | 需要标注数据 | 速度 | 效果 | 成本 |
|---|---|---|---|---|---|
| **随机森林** | 要 | 要 | 快 | 中 | 低 |
| **fasttext** | 要 | 要 | 极快 | 中上 | 低 |
| **BERT 微调** | 要 | 要（可少） | 中 | 高 | 中 |
| **LLM 提示词** | 不要 | 少量示例即可 | 慢 | 中高（看任务） | 按 token① |
| **模型压缩** | —— | —— | 优化后更快 | 略降 | 低 |

> ① LLM 方案单次便宜但量大就贵；微调一次性投入大但长期单次成本低。

> 🔥 **这套对比就是面试的核心素材**：不是"我会用 BERT"，而是"我知道四个方案各自适用什么场景"。

## 三、初识：数据集与任务定义

### 3.1 任务形式

**多分类**：输入一段文本（新闻标题+正文/短资讯），输出一个类别标签（历史、军事、体育、旅行、娱乐、美妆……）。

```python
# 数据样例（示意）
{"text": "二战期间某战役的战术分析……", "label": "军事"}
{"text": "新款面霜的成分与使用方法……", "label": "美妆"}
```

### 3.2 数据要关注什么（面试常问）

| 关注点 | 为什么 |
|---|---|
| **类别分布** | 是否严重不均衡（会影响评估与训练策略） |
| **文本长度** | 决定截断长度（BERT 通常 512，fasttext 影响小） |
| **数据来源与标注质量** | 标注噪声是效果天花板 |
| **训练/测试划分** | 必须避免泄漏（同源文档别跨集） |

### 3.3 评测指标

| 指标 | 用途 |
|---|---|
| **Accuracy** | 整体正确率（类别均衡时可用） |
| **F1（macro）** | 类别不均衡时更可靠 |
| 各类别 P/R | 找出"哪个类别拖后腿" |
| **推理速度 / 成本** | 工程侧的关键指标 |

> 📌 这个项目特别值得学的一点：**不只比准确率，还比速度和成本**——这才是真实的工程选型。

## 四、初识：工程结构

项目用统一的结构管理各方案，便于对比：

```text
config/          # 路径与参数统一配置（改一处生效全局）
  └── paths.py   # 数据集、模型、输出目录
data/            # 原始数据与处理后数据
models/          # 四种方案的训练脚本
  ├── rf/        # 随机森林
  ├── fasttext/  # fasttext
  ├── bert/      # BERT 微调
  └── llm/       # LLM 提示词
service/         # 预测入口（统一接口，方便前端调用）
```

> 💡 **config 统一管理**是个小细节大价值：所有方案共用一套路径配置，切换数据集/输出目录只改一个文件——面试时可以提一句"工程规范"。

## 六、总结

### 6.1 要点回顾

1. 业务：推荐系统的**文本分类子模块**——分对类才能"投满分"
2. 四种方案：**随机森林 → fasttext → BERT 微调 → LLM 提示词**，覆盖从手工特征到免训练的完整演进
3. 选型不只看准确率：**速度、成本、数据需求、更新成本**都要比
4. 数据关注：类别分布、文本长度、标注质量、划分泄漏
5. 工程规范：**config 统一管理**，各方案统一接口便于对比与上线
