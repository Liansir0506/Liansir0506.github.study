> **一句话概括**：Coze 是把"提示词 + 插件 + 工作流 + 知识库"打包成可视化产品的平台——不写代码，也能做出一个能用的 AI 应用。

## 一、初识：Coze 是什么

**Coze（扣子）** 是字节跳动出的 AI Bot 搭建平台。同类产品还有 OpenAI 的 GPTs、Dify、FastGPT。

一句话：**把"调用大模型 + 搜索引擎 + 各种工具 + 私有数据"这些能力，做成拖拽配置就能用的产品。**

你不需要写 Python、不需要调 API，只需要：

- 写一段人设（Prompt）
- 选几个插件
- 需要的话画个工作流
- 点"发布"

一个能用的 AI 应用就上线了——可以发到飞书、微信、网页等各种渠道。

### 1.1 平台 vs 写代码

| | 低代码平台（Coze） | 自己写代码 |
|---|---|---|
| 上手速度 | 快（小时级） | 慢（天/周级） |
| 灵活性 | 受平台限制 | 完全自由 |
| 定制化 UI | 只能用平台提供的 | 随便设计 |
| 高并发/私有部署 | 受限 | 可控 |
| 适合 | **快速验证、内部工具、非核心业务** | **核心产品、定制化、规模化** |

> 📌 面试里常问："你会用 Coze 还是自己写？"——答"看场景"：验证阶段用 Coze 快速跑通，规模化和定制化再迁移到代码（AI 面试助手那个项目就是这么决策的，见 coze-05）。

## 二、初识：五大核心概念

这一篇本质是"地图"，五个概念后面每篇展开一个：

| 概念 | 是什么 | 对应前面学的 |
|---|---|---|
| **Bot / 智能体** | 一个配好的 AI 应用（人设+能力） | Prompt + 工具 |
| **人设与回复逻辑** | 写 Prompt 的地方（角色/规则/格式） | pe-01 提示词基础 |
| **插件（Plugin）** | 外部能力：搜索、天气、绘图、HTTP | **Function Calling**（pe-03） |
| **工作流（Workflow）** | 可视化多步骤编排 | **链式提示 + 程序编排**（pe-02） |
| **知识库（Knowledge）** | 上传私有文档，让 Bot 能查 | **RAG**（检索增强生成） |

> 🔥 看到没——Coze 的每个功能，都能在之前学的概念里找到原型。**平台只是把代码包装成了界面，原理没变。**

## 三、运用：第一个 Bot 怎么搭

以"读书笔记助手"为例，四个步骤：

### 3.1 第一步：写人设（Prompt）

这就是 pe-01 的 Prompt 五要素，直接搬进"人设与回复逻辑"：

```text
# 角色
你是一名读书笔记助手，帮助用户把书籍内容整理成结构化笔记。

# 技能
1. 用户提供书名或内容，你输出「核心观点 / 金句摘录 / 我的思考」三部分
2. 观点必须来自用户提供的内容，不要编造
3. 输出用 Markdown，不超过 500 字

# 限制
- 只处理书籍相关内容，其他问题礼貌拒绝
- 不确定的信息标注"需核实"
```

### 3.2 第二步：选模型

Coze 里可以选不同模型（豆包、通义、DeepSeek、GPT 等），按任务选：

| 任务 | 建议 |
|---|---|
| 简单对话/分类 | 小模型（快、便宜） |
| 复杂推理/长文 | 大模型（准、贵） |

### 3.3 第三步：加技能（插件 / 工作流 / 知识库）

按需添加：

- 要联网搜索 → 加"搜索"插件
- 要按固定流程处理 → 加工作流
- 要查自己的资料 → 加知识库

### 3.4 第四步：调试与发布

平台右侧可以直接对话测试：改一句 Prompt、立刻看效果——这个"改-测"循环比写代码快得多。

满意后点发布，选择渠道（飞书、微信公众号、网页链接、API）。

## 四、总结

### 4.1 要点回顾

1. Coze = 低代码 AI Bot 平台，把 Prompt/插件/工作流/知识库做成可视化配置
2. 五大概念：**Bot、人设（Prompt）、插件（Function Calling）、工作流（链式编排）、知识库（RAG）**
3. 搭 Bot 四步：**写人设 → 选模型 → 加技能 → 调试发布**
4. 平台适合快速验证和非核心业务；定制化/规模化要回到代码
5. 平台不改变原理——**会用 Coze 的前提是懂 Prompt、工具调用这些底层概念**

<summary>Q1：Coze 的插件对应你学过的哪个概念？</summary>

Function Calling（工具调用）。插件就是预先封装好的工具，平台负责把工具描述传给模型、执行调用、回填结果。

<summary>Q2：什么时候该用低代码平台，什么时候该写代码？</summary>

验证想法、内部工具、非核心业务 → 低代码；核心产品、需要定制 UI/高并发/私有部署 → 写代码。
</details>

<details>
<summary>Q3：搭一个 Bot 的四步？</summary>

写人设（Prompt）→ 选模型 → 加技能（插件/工作流/知识库）→ 调试并发布。
</details>

| 面试问法 | 答题要点 |
|---|---|
| 用过哪些 AI 应用平台？ | Coze / Dify / FastGPT / GPTs；说清各自定位与低代码的取舍 |

| 低代码平台和自研怎么选？ | 验证期用平台抢时间；核心业务自研保证扩展性与可控性 |
