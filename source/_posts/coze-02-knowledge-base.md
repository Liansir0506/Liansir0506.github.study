## 一、初识：模型为什么"不懂你的资料"

大模型的知识来自训练数据——它知道维基百科，但不知道：

- 你公司的产品手册
- 你们团队的技术文档
- 你个人的笔记

而且它还有两个硬伤：

| 问题 | 表现 |
|---|---|
| **知识截止** | 训练之后发生的事它不知道 |
| **幻觉** | 不知道也敢编（"一本正经地胡说八道"） |

**知识库（Knowledge Base）** 就是解法：把私有资料变成一个"可以随时查的资料柜"，回答前先查资料，再基于资料回答。

> 这套做法的正式名字叫 **RAG（Retrieval-Augmented Generation，检索增强生成）**——先检索、再生成。

## 二、初识：知识库的完整流程（就是 RAG 的流程）

```text
① 上传文档（PDF / Word / Markdown / 网页）
   ↓
② 切片（Chunk）：长文档切成小段（如每段 500 字，段间留 50 字重叠）
   ↓
③ 向量化（Embedding）：每段 → 一个向量（nlp-02 学的词向量，进阶版）
   ↓
④ 存入向量库
   ↓
⑤ 用户提问 → 问题也转向量 → 找最相似的 N 段 → 拼进 Prompt → 模型基于资料回答
```

前四步是**预处理**（上传一次就完成）；第五步是**在线检索**（每次提问都跑）。

> 🔥 对照 nlp-02：那边讲"词 → 向量"，这里讲"文档片段 → 向量"。原理相同——**语义相近 = 向量距离近**。区别只是规模：知识库动辄几万段，必须用专门的向量数据库。

### 2.1 为什么不能直接塞进 Prompt

有人会想：为什么不把文档全文塞进 Prompt 让模型自己看？

| 问题 | 说明 |
|---|---|
| **上下文长度有限** | 一份 100 页的文档就超了 |
| **成本和延迟** | 每次提问都塞全文，token 费用爆炸、响应变慢 |
| **信息淹没** | 上下文太长时，模型容易忽略真正相关的内容（"大海捞针"） |

**RAG 的聪明之处：只把"最相关的几段"塞进去**——又省又准。

## 三、运用：Coze 知识库怎么配

### 3.1 基本操作

1. 创建知识库 → 上传文档（支持 PDF、Word、TXT、网页链接、API 导入）
2. 平台自动：切片 → 向量化 → 入库
3. 在 Bot 的人设里，"技能"处添加知识库
4. 对话时，Bot 会先检索知识库再回答

### 3.2 三个关键参数

| 参数 | 作用 | 建议 |
|---|---|---|
| **切片大小（chunk size）** | 每段多长 | 300~800 字；太大检索不准，太小语义不完整 |
| **重叠长度（overlap）** | 相邻段重叠多少 | 10%~20%；防止关键句被切断 |
| **召回数量（top k）** | 检索几段 | 3~5 段；太多会喂冗余信息，太少可能漏 |

### 3.3 效果调优的四个方向

| 问题 | 调什么 |
|---|---|
| 检索不到相关内容 | 换更好的 embedding 模型、调整切片大小 |
| 检索到但不相关 | 减小 top k、加相似度阈值、优化文档结构（标题/分段） |
| 回答不完整 | 增大 top k、减小切片、加大重叠 |
| 回答编造 | Prompt 里加"只根据资料回答，没有就说不知道" |

> 📌 这就是 RAG 项目的核心调优点——**"检索质量"决定"回答质量"**。等写 RAG 项目时会系统展开（混合检索、重排、查询改写）。

## 四、初识：知识库 vs 微调（常被问的问题）

"要让模型懂我的资料，是知识库还是微调？"——面试高频。

| | 知识库（RAG） | 微调（Fine-tuning） |
|---|---|---|
| 本质 | 检索外部资料 | 改模型参数 |
| 适合 | **事实类知识**（文档、手册、FAQ） | **风格/格式/领域能力**（语气、输出规范） |
| 更新 | 改文档即可，即时生效 | 要重新训练 |
| 成本 | 低 | 高（数据+算力） |
| 幻觉 | 可缓解（有出处） | 仍可能存在 |

> 🔥 总结一句：**"知识查得到就用 RAG，风格学得像才用微调"**。大部分企业场景是 RAG，因为知识更新快、要可追溯。

## 五、总结

### 5.1 要点回顾

1. 大模型的硬伤：知识截止、幻觉——知识库是"外挂资料柜"
2. 知识库 = **RAG 的可视化版**：上传 → 切片 → 向量化 → 存储 → 检索 → 生成
3. 为什么不能塞全文：上下文有限、成本高、信息淹没
4. 三个关键参数：**切片大小、重叠长度、召回数量**
5. RAG vs 微调：**知识查得到用 RAG，风格学得像用微调**

### 5.2 自测清单

<details>
<summary>Q1：知识库的完整流程？</summary>

上传文档 → 切片 → embedding 向量化 → 存入向量库 → 提问时问题也向量化 → 检索最相似的 N 段 → 拼入 Prompt 生成回答。
</details>

<details>
<summary>Q2：为什么切片要留重叠？</summary>

避免关键信息刚好被切在边界上（比如一句话的后半段在下一块），重叠能保证语义完整。
</details>

<details>
<summary>Q3：知识库和微调怎么选？</summary>

事实类知识（文档、FAQ）用知识库（RAG）：更新快、可追溯、成本低；要改变输出风格/领域能力用微调。
</details>

<details>
<summary>Q4：检索质量差怎么优化？</summary>

换 embedding 模型、调切片大小/重叠、优化文档结构、调整 top k 和相似度阈值；进阶手段有混合检索、重排、查询改写。
</details>

### 5.3 面试视角（🔥）

| 面试问法 | 答题要点 |
|---|---|
| 什么是 RAG？流程？ | 检索增强生成：文档切片→向量化→入库→检索 top-k→拼 Prompt 生成 |
| RAG 和微调的区别？ | 外挂知识 vs 改参数；更新快 vs 成本高；事实 vs 风格 |
| 切片怎么设置？ | 按文档结构切，300~800 字，10%~20% 重叠，保持语义完整 |
| 怎么评估 RAG 效果？ | 检索侧（召回率/命中率）+ 生成侧（忠实度/相关性），人工抽样 |
| RAG 常见问题？ | 检索不到、检索冗余、多跳问题、回答不忠实、文档更新不同步 |
