## 一、初识：Embedding 的本质

### 1.1 一句话

**Embedding = 把文本映射到高维空间里的一个点，语义相近的文本，点也相近。**

```text
"怎么退款"      → [0.21, -0.08, 0.93, ...]   （1024 维）
"退款的流程"    → [0.19, -0.11, 0.90, ...]   ← 距离很近
"公司的年假"    → [-0.45, 0.33, -0.12, ...]  ← 距离很远
```

### 1.2 常用中文 Embedding 模型

| 模型 | 维度 | 特点 |
|---|---|---|
| **BGE-M3** | 1024 | 支持多语言、长文本，当前主流 |
| BGE-large-zh | 1024 | 中文效果好 |
| text-embedding-v3（阿里） | 1024/768 | API 调用方便 |
| m3e-base | 768 | 轻量、适合本地 |

> 📌 选型要点：**中文效果 > 维度大小 > 推理成本**。项目里通常固定一个模型，**入库和查询必须一致**。

### 1.3 相似度怎么算

最常用**余弦相似度**：

$$\cos(\theta) = \frac{A \cdot B}{|A| \cdot |B|}$$

取值 [-1, 1]，越接近 1 越相似。工程上还会用内积（IP）或欧氏距离（L2）——**关键是要和建索引时的度量方式一致**。

## 二、初识：向量检索与 ANN 索引

### 2.1 暴力检索的问题

100 万个 chunk × 1024 维，每次查询都算一遍相似度——太慢。

**ANN（Approximate Nearest Neighbor，近似最近邻）** 的思路：牺牲一点点精度，换极大的速度。

### 2.2 HNSW：最常用的 ANN 索引

**HNSW（Hierarchical Navigable Small World，分层可导航小世界）** 是目前最主流的向量索引：

```text
第 2 层（最稀疏）：  A ——————— F
                      \       /
第 1 层（中等）：   A — B — D — F — G
                     \  |  /
第 0 层（全部点）： A-B-C-D-E-F-G-H...
```

思想：**像坐高铁一样分层跳转**——先在高层的稀疏图里快速接近目标区域，再逐层下降精细查找。

关键参数（面试常问）：

| 参数 | 作用 | 调大的影响 |
|---|---|---|
| **M** | 每个节点的最大连接数 | 召回更高、内存更大 |
| **efConstruction** | 建索引时的搜索范围 | 建索引更慢、图质量更好 |
| **ef**（查询时） | 查询时的搜索范围 | 召回更高、查询更慢 |

> 🔥 一句话总结：**M 和 efConstruction 决定"图建得好不好"（离线），ef 决定"查得准不准"（在线）。**

## 三、初识：Dense vs Sparse——两种召回各有短板

| | **Dense（稠密向量）** | **Sparse（稀疏/BM25）** |
|---|---|---|
| 表示 | 1024 维浮点向量 | 词权重（词表维度，大量 0） |
| 擅长 | 语义相近（"退款"≈"退钱"） | 精确词匹配（型号、法条号、专有名词） |
| 短板 | 精确匹配弱、对罕见词不敏感 | 不懂同义词、分词依赖重 |
| 典型 | BGE embedding | BM25 |

### 3.1 为什么必须混合

真实问题里两种需求同时存在：

```text
问题 A："怎么退钱？"          → 需要语义（文档里写的是"退款流程"）
问题 B："XR-2000 怎么重置？"  → 需要精确匹配型号（语义模型可能忽略 XR-2000）
```

**混合检索 = Dense + Sparse 双路召回 + 融合排序**——两边的短板互相补上。

> 融合方式（RRF）和 Reranker 精排，在 ragp-08 详细展开。

## 四、初识：怎么衡量检索质量（评测指标）

| 指标 | 定义 | 说明 |
|---|---|---|
| **Recall@K（召回率）** | 正确片段是否出现在前 K 条里 | 检索阶段最核心的指标 |
| **Hit Rate（命中率）** | 前 K 条里至少有一条正确 | 简化的召回指标 |
| **MRR（平均倒数排名）** | 正确结果排名的倒数的平均 | 关心"排得多靠前" |
| **NDCG** | 考虑排序位置的加权指标 | 有多个相关结果时更合理 |

> 📌 工程实践：构造"问题 → 应命中 chunk"的测试集，**先量 Recall@5，再看最终回答质量**——检索都召回不到，后面全是白搭。

## 五、总结

### 5.1 要点回顾

1. **Embedding**：文本 → 高维点，语义近则距离近；入库和查询必须用同一模型
2. **ANN / HNSW**：分层图结构，牺牲精度换速度；关键参数 **M、efConstruction（建图）、ef（查询）**
3. **Dense vs Sparse**：语义 vs 精确；真实问题两者都需要 → **混合检索**
4. 评测：**Recall@K / Hit Rate / MRR / NDCG**，先保召回再谈生成
5. "检索不到，一切归零"——RAG 的效果上限由检索决定

### 5.2 自测清单

<details>
<summary>Q1：Embedding 模型为什么必须统一？</summary>

不同模型的向量空间不兼容，同一段文本用不同模型编码出的向量无法比较相似度；换模型必须重建全部索引。
</details>

<details>
<summary>Q2：HNSW 的 M 和 ef 分别影响什么？</summary>

M 是图中每个节点的连接数（建图阶段，影响内存与图质量）；ef 是查询时的候选搜索范围（影响召回率与查询延迟）。
</details>

<details>
<summary>Q3：为什么 Dense 检索需要搭配 BM25？</summary>

Dense 擅长语义但精确匹配弱（型号、编号、专有名词容易漏），BM25 基于关键词能精准命中；两者互补。
</details>

<details>
<summary>Q4：Recall@K 和最终回答质量的关系？</summary>

召回是上限：正确片段不在召回结果里，生成再强也答不对。所以优化 RAG 先看 Recall@K，再看生成质量。
</details>

### 5.3 面试视角（🔥🔥）

| 面试问法 | 答题要点 |
|---|---|
| 向量检索的原理？ | embedding 编码 + 相似度计算 + ANN 索引加速（HNSW） |
| HNSW 为什么快？ | 分层图，先高层粗跳、逐层细化，近似最近邻 |
| 为什么要混合检索？ | Dense 懂语义弱精确、BM25 精确弱语义，互补提升召回 |
| 怎么评估检索质量？ | 评测集 + Recall@K / HitRate / MRR；再结合生成质量评估 |
| 常见的 embedding 模型？ | BGE-M3、BGE-large-zh、text-embedding-v3；按中文效果与成本选 |
