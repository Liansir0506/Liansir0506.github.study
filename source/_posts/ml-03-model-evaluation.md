## 一、初识：99% 的准确率，为什么可能是废的

### 1.1 一个反直觉的例子

假设 1000 笔交易里，990 笔正常、10 笔是欺诈。现在有个"傻瓜模型"：**不管输入什么，一律预测"正常"**。

它的准确率是多少？

$$\frac{990}{1000} = 99\%$$

看着很漂亮。但它一笔欺诈都抓不出来——对银行来说，这个模型的价值是 **0**。

**这就是"准确率陷阱"：在类别不平衡的场景（欺诈检测、疾病筛查、故障告警）里，准确率会严重高估模型。**

### 1.2 问题出在哪？—— 我们只算了"总分"

准确率只看"猜对了多少个"，不看"**猜错了什么**"。

要看清模型到底哪好哪坏，得把预测结果拆成四块——这就是**混淆矩阵（Confusion Matrix）**。

## 二、初识：混淆矩阵 —— 评估的地基

把"真实情况"和"模型预测"交叉一下，就得到四个格子：

|  | 预测：正 | 预测：负 |
|---|---|---|
| **真实：正** | **TP**（真正例）猜对了 | **FN**（假负例）漏报了 |
| **真实：负** | **FP**（假正例）误报了 | **TN**（真负例）猜对了 |

四个字母记住方法：第一个字母（T/F）= 判对没；第二个字母（P/N）= 模型判成了什么。

- **TP**：真·是正例，判成正 —— 抓对了
- **FN**：真·是正例，判成负 —— **漏报**（最怕这个）
- **FP**：真·是负例，判成正 —— **误报**（虚惊一场）
- **TN**：真·是负例，判成负 —— 正确排除

### 2.1 四个指标，从混淆矩阵里长出来

| 指标 | 公式 | 一句话 | 关注什么 |
|---|---|---|---|
| **准确率** Accuracy | (TP+TN) / 全部 | 总分 | 总体猜对比例（样本不平衡时失真） |
| **精确率** Precision | TP / (TP+FP) | **查得准不准** | 报警的里面，有多少是真的 |
| **召回率** Recall | TP / (TP+FN) | **查得全不全** | 真的里面，抓到了多少 |
| **F1** | 2PR / (P+R) | 精确率和召回率的**调和平均** | 两者都要时用 |

> 用"抓小偷"记最方便：**精确率 = 抓的人里有多少真是小偷；召回率 = 小偷里抓到了几个。**
> 宁可抓错也不能放过 → 看召回率；宁可放过也别冤枉好人 → 看精确率。

### 2.2 🔥 什么时候看哪个指标（面试高频追问）

这才是真正值钱的部分——**指标不是越高越好，要看业务场景**：

| 场景 | 更应该看 | 为什么 |
|---|---|---|
| **癌症筛查** | 召回率 | 漏诊会耽误治疗，宁可误报（复查确认） |
| **垃圾邮件过滤** | 精确率 | 把老板的邮件当垃圾，后果严重；漏一封垃圾无所谓 |
| **欺诈检测** | 召回率（辅以精确率） | 漏掉欺诈损失大，但误报太多也会骚扰用户 |
| **推荐系统** | 精确率（Top-K） | 推的东西要准，推错了掉体验 |

> 面试被问"你的模型准确率 99%，够好吗？"——别急着答"好"，先反问：**"正负样本比例是多少？业务更怕漏报还是误报？"** 这个反问本身就是加分项。

## 三、运用：模型评估的三件套

### 3.1 第一件：为什么要把数据"交叉"着用

如果只做一次训练/测试划分（比如 8:2），有一个隐患：**划分的偶然性**。万一测试集恰好都是简单样本，分数虚高；下次换一批又暴跌。

**交叉验证（Cross Validation）** 的解法很简单：

1. 把数据分成 K 份（一般 K=4 或 5）
2. 轮流拿其中 1 份当测试集、其余当训练集 → 训练 K 次，得到 K 个分数
3. 取平均

```python
from sklearn.model_selection import cross_val_score

scores = cross_val_score(model, x, y, cv=4)   # 4 折交叉验证
print(scores)          # 每次的分数，如 [0.93 0.95 0.94 0.92]
print(scores.mean())   # 平均分 → 比单次划分可靠得多
```

> 一句话：**数据少的时候，交叉验证能让评估结果更稳、更有说服力。**

### 3.2 第二件：网格搜索 —— 让机器自动试参数

先分清两个概念：

| 概念 | 谁定的 | 例子 |
|---|---|---|
| **参数** | 模型自己学的 | 线性回归的 w、b |
| **超参数** | 人定的 | KNN 的 K、决策树的 max_depth、学习率 |

超参数靠人猜太慢，**网格搜索（Grid Search）** 就是把候选值排列组合全试一遍，用交叉验证打分，挑最好的：

```python
from sklearn.model_selection import GridSearchCV

param_grid = {"n_neighbors": [1, 3, 5, 7, 9]}       # 要试的候选值
grid = GridSearchCV(KNeighborsClassifier(), param_grid, cv=4)
grid.fit(x_train, y_train)

print(grid.best_params_)   # 最优超参，如 {'n_neighbors': 5}
print(grid.best_score_)    # 对应的交叉验证平均分
```

> 📌 注意：网格搜索 = **穷举 + 交叉验证**。参数组合一多，计算量会爆炸——所以实际工作中常先粗调范围，再细调局部。

### 3.3 第三件：一份报告看全所有指标

实际项目里最常用的不是一个个算指标，而是直接打一份"体检报告"：

```python
from sklearn.metrics import classification_report, confusion_matrix, accuracy_score

print(confusion_matrix(y_test, y_pred))     # 混淆矩阵
print(classification_report(y_test, y_pred))  # 精确率/召回率/F1 全在里面
```

`classification_report` 输出示例：

```text
              precision    recall  f1-score   support
           0       0.91      0.95      0.93       100
           1       0.88      0.80      0.84        50
    accuracy                           0.90       150
```

怎么读：**每一行是一个类别**；`support` 是该类的样本数；重点看**样本少的类别**的 recall 和 f1——整体 accuracy 会被大类别拉高，掩盖小类别的糟糕表现。

### 3.4 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| `precision_score` 报错 | 二分类默认正类是 1，你的标签不是 | 传 `pos_label` 指定 |
| 准确率高但业务效果差 | 只看 accuracy，忽略不平衡 | 看 P/R/F1 和混淆矩阵 |
| 交叉验证分数很高，上线就崩 | 数据泄漏（缩放/特征选择在划分前做了） | 先划分，再缩放（用 Pipeline 更稳） |
| 网格搜索跑了一天 | 参数组合太多 | 缩小范围、改随机搜索（RandomizedSearchCV） |

## 四、总结

### 4.1 要点回顾

1. **准确率会在类别不平衡时说谎**——99% 可能毫无价值
2. 混淆矩阵是根：**TP / FP / FN / TN**
3. **精确率 = 查得准（TP/(TP+FP)）；召回率 = 查得全（TP/(TP+FN)）；F1 = 两者的调和平均**
4. **业务场景决定看哪个指标**：癌症筛查看召回，垃圾邮件看精确
5. 交叉验证减少评估偶然性；网格搜索（穷举 + 交叉验证）自动找最优超参

### 4.2 自测清单

<details>
<summary>Q1：为什么"默认全猜正常"也能有 99% 准确率？</summary>

因为样本严重不平衡（990 正常 vs 10 欺诈）。accuracy 只看总分，不看漏掉了多少欺诈样本。所以必须看召回率和混淆矩阵。
</details>

<details>
<summary>Q2：精确率和召回率，分别回答什么问题？</summary>

精确率：报警的里面有多少是真的（查得准不准）；召回率：真的里面抓到了多少（查得全不全）。
</details>

<details>
<summary>Q3：F1 为什么用调和平均，不用算术平均？</summary>

调和平均对"短板"更敏感：精确率和召回率只要有一个很低，F1 就会被拉低，逼着你两个都要顾。
</details>

<details>
<summary>Q4：交叉验证解决什么问题？</summary>

减少单次数据划分带来的偶然性，让评估结果更稳定可靠（尤其是数据量小的时候）。
</details>

### 4.3 面试视角（🔥 必背）

| 面试问法 | 答题要点 |
|---|---|
| 准确率有什么问题？ | 类别不平衡时失真；要看 P/R/F1 与混淆矩阵 |
| 精确率和召回率的区别？举例说明 | TP/(TP+FP) vs TP/(TP+FN)；癌症看召回、垃圾邮件看精确 |
| F1 是什么？ | P 和 R 的调和平均，对短板敏感 |
| 不做交叉验证会怎样？ | 单次划分有偶然性，评估不稳 |
| 超参数怎么调？ | 网格搜索 + 交叉验证；参数组合多时用随机搜索 / 贝叶斯优化 |
| 数据泄漏是什么？ | 训练时用到了测试集信息（如先缩放后划分），导致评估虚高 |
| RAG 里怎么用这些指标？ | 检索质量看召回率（该找的找到了吗）、精确率（找回来的有多少相关）；生成质量另有评估（忠实度/相关性） |
