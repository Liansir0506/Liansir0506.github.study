## 一、初识：没有标签，算法在学什么

前面所有算法（线性回归、KNN、决策树、随机森林）都是**监督学习**：数据带着"标准答案"（标签），模型学的是"输入 → 输出"的映射。

但现实里，大量数据**没有标签**——比如一堆用户的消费记录，没人告诉你"这是哪类客户"。

无监督学习就是在这种情况下工作的：**没有答案，那就自己找"结构"。**

聚类（Clustering）是最典型的无监督任务：**把相似的样本自动归到一组（簇，cluster）**，让"同组内尽量像，不同组尽量不像"。

> 生活例子：超市想给会员分群做精准营销。没人提前标注"谁是价格敏感型、谁是品质型"——只能靠消费数据本身，让算法把行为相似的人聚在一起，再由人来看图说话、给每群起个名字。

### 1.1 聚类 vs 分类，别搞混

| | 分类（监督） | 聚类（无监督） |
|---|---|---|
| 有没有标签 | 有，训练时就知道每类的正确答案 | **没有**，事先不知道有几类、是什么类 |
| 目标 | 学"输入 → 已知类别" | 发现数据里的自然分组 |
| 结果含义 | 类别含义明确（猫/狗） | 簇的含义要人**事后解读** |

## 二、初识：KMeans 是怎么回事（五步）

KMeans 是聚类里最常用的算法，名字里两个词就把核心说完了：**K = 分成几堆，Means = 用均值当簇的中心**。

整个流程就五步：

| 步骤 | 做什么 |
|---|---|
| 1 | 定 K：要分成几堆（人定的） |
| 2 | 随机挑 K 个样本，作为初始"簇心" |
| 3 | 每个样本算到各簇心的距离，**归到最近的那一堆** |
| 4 | 每堆重新算**平均值**，作为新的簇心 |
| 5 | 重复 3、4，直到簇心不再移动（收敛） |

用大白话讲：**先随便插几面旗，大家往最近的旗子靠；然后每面旗挪到人群中心；再重新站队……来回几次，队伍就稳定了。**

## 三、初识：K 到底怎么定？

KMeans 最大的尴尬：**K 得人给**，但人往往不知道数据该分几类。

行业里有两个常用工具：

### 3.1 SSE 肘部法（最常用）

**SSE（误差平方和）**：每个样本到它所属簇心的距离平方之和——衡量"簇内有多紧"。

规律：**K 越大，SSE 一定越小**（分开的堆越多，当然越"紧"）。所以不能直接选 SSE 最小的。

做法：把 K = 1, 2, 3, 4, 5… 各跑一遍，画出 SSE 随 K 变化的曲线，找那个"**拐点（肘部）**"——再往后 K 增大，SSE 下降明显变缓，说明多分意义不大了。

### 3.2 SC 轮廓系数

**轮廓系数（Silhouette Coefficient，SC）**：综合考虑"簇内紧不紧、簇间远不远"，取值 -1 ~ 1。

- 越接近 1：簇内抱得紧、簇间离得开（分得好）
- 接近 0：簇之间边界模糊
- 小于 0：样本可能被分错簇了

实际做法：**按 SC 挑 K**，或者用 SSE 肘部法定个大概、再用 SC 验证。

## 四、运用：用户画像聚类（完整流程）

用"客户消费数据"练一遍。**注意：KMeans 也吃距离，所以第一步还得标准化。**

```python
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.cluster import KMeans
from sklearn.preprocessing import StandardScaler

# 1. 准备数据：客户 ID / 年收入 / 消费分数（常见的 mall customers 数据集）
data = pd.read_csv("customers.csv")
x = data[["Annual Income (k$)", "Spending Score (1-100)"]]

# 2. 标准化：收入单位是 k$、消费分数是 1-100，量纲不同，必须缩放
scaler = StandardScaler()
x_scaled = scaler.fit_transform(x)

# 3. 用 SSE 肘部法找 K
sse = []
for k in range(1, 11):
    km = KMeans(n_clusters=k, random_state=42, n_init=10)
    km.fit(x_scaled)
    sse.append(km.inertia_)      # inertia_ 就是 SSE

plt.plot(range(1, 11), sse, marker="o")
plt.xlabel("K"); plt.ylabel("SSE"); plt.title("Elbow Method")
plt.show()   # 图里找"拐点"，比如 K=5

# 4. 用选定的 K 正式聚类
km = KMeans(n_clusters=5, random_state=42, n_init=10)
labels = km.fit_predict(x_scaled)
data["cluster"] = labels

# 5. 解读每一簇：看各簇的均值画像
print(data.groupby("cluster")[["Annual Income (k$)", "Spending Score (1-100)"]].mean())
```

最后一步才是**业务价值**：把每簇的均值摆出来，人工给它们起名字，比如：

| 簇 | 特征 | 起个名 |
|---|---|---|
| 0 | 高收入、高消费 | 高价值客户（重点维护） |
| 1 | 低收入、低消费 | 保守型（低成本触达） |
| 2 | 高收入、低消费 | 潜力客户（重点挖掘） |
| … | … | … |

> 💡 记住这个顺序：**先算 SSE 定 K → 再聚类 → 最后按簇看均值、起名字**。这是聚类项目的标准动作。

### 4.1 顺手学一个技巧：布尔索引

聚类结果是一列标签，实战里经常要"把某一簇的原始数据捞出来看"，用 NumPy 的布尔索引：

```python
import numpy as np

arr = np.array([4, 3, 4, 2, 0, 1])   # 每个样本的簇标签

print(arr > 2)        # [True False True False False False]
print(arr[arr > 2])   # [4 4]  → 只保留满足条件的元素
print(data[labels == 0])   # 从原数据里捞出"第 0 簇"的所有客户
```

> 这种写法在数据处理里到处都是，值得记住。

### 4.2 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 每次跑结果都不一样 | 初始簇心随机 | 设 `random_state` |
| 聚类结果毫无意义 | 没标准化，量纲大的特征主导距离 | `StandardScaler` |
| 不知道 K 取几 | —— | SSE 肘部法 + 轮廓系数 |
| 聚类结果里出现"一个超大的簇" | K 太小 / 数据分布不均 | 调 K，或换 DBSCAN 等算法 |

## 五、KMeans 的局限（面试常问）

| 局限 | 说明 | 缓解方法 |
|---|---|---|
| 必须**预先指定 K** | 人得先猜分类数 | 肘部法 / 轮廓系数 / 业务经验 |
| 对**初始簇心**敏感 | 不同初始化可能得到不同结果 | `n_init` 多次初始化取最优，`k-means++` |
| 只能发现**球形簇** | 长条形、环形分布聚不好 | 换 DBSCAN / 谱聚类 |
| 对**量纲**敏感 | 大数值特征会主导距离 | 标准化 |
| 对**异常值**敏感 | 均值容易被极端值带偏 | 清洗异常值，或换 K-Medoids |

## 六、💡 顺手埋个伏笔：聚类和 RAG 的关系

等以后写 RAG 项目时会发现，聚类在检索系统里很实用：

- **语义去重**：把语义相近的文档聚在一起，去掉重复内容
- **主题归类**：自动给知识库文档打主题标签
- **减少检索冗余**：多条相似结果只保留代表

思路完全一样：**用向量之间的距离衡量相似度 → 聚成一堆**。区别只是——这里的特征是数值表格，那里是文本向量（embedding）。

## 七、总结

### 7.1 要点回顾

1. 聚类是**无监督**学习：没有标签，靠"相似度"自动分组
2. KMeans 五步：定 K → 选初始簇心 → 按最近距离分配 → 重算均值 → 迭代到稳定
3. K 怎么定：**SSE 肘部法**（找拐点）+ **SC 轮廓系数**（越大越好）
4. 实战流程：标准化 → 定 K → 聚类 → 按簇看均值 → 给簇起名字
5. KMeans 的局限：要指定 K、对初始值/量纲/异常值敏感、只擅长球形簇

### 7.2 自测清单

<details>
<summary>Q1：聚类和分类的区别？</summary>

分类是有监督（训练数据带标签，学映射）；聚类是无监督（没有标签，自动发现数据分组结构）。
</details>

<details>
<summary>Q2：KMeans 的迭代过程讲一遍？</summary>

定 K → 随机初始化 K 个簇心 → 样本归到最近的簇 → 重算各簇均值作为新簇心 → 直到簇心不再变化。
</details>

<details>
<summary>Q3：SSE 越小越好吗？为什么用肘部法？</summary>

SSE 随 K 增大单调减小，直接取最小没有意义。肘部法看"下降速度的拐点"：拐点前增大 K 收益明显，拐点后收益饱和，那个 K 就是合理选择。
</details>

<details>
<summary>Q4：KMeans 有什么缺点？</summary>

K 要人工指定；对初始簇心敏感；只能发现球形簇；对量纲和异常值敏感。
</details>

### 7.3 面试视角（📌）

| 面试问法 | 答题要点 |
|---|---|
| KMeans 的原理？ | 迭代：分配样本到最近簇心 → 更新簇心为均值 → 收敛 |
| K 怎么选？ | 肘部法（SSE 拐点）+ 轮廓系数（越接近 1 越好）+ 业务经验 |
| KMeans 的缺点？ | 需指定 K、初始值敏感（k-means++ 缓解）、仅球形簇、对量纲/异常值敏感 |
| KMeans 和 KNN 的区别？ | KMeans 是无监督聚类（找簇），KNN 是监督分类（找邻居）；前者 K 是簇数，后者 K 是邻居数 |
| 聚类结果怎么评估？ | 内部指标：SSE、轮廓系数；有真标签时可用 ARI/NMI |
