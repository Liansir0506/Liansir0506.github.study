## 一、初识：文本为什么特殊

处理文本之前，要先解决两个问题：

1. **词不是数字**：模型只吃张量，"猫""狗""汽车"怎么变成数字？
2. **顺序很重要**："我 打 你" 和 "你 打 我"，词一样但意思完全不同

第一个问题用**词嵌入**解决，第二个问题用**循环神经网络（RNN）**解决。

## 二、初识：词嵌入 Embedding（🔥 RAG 的地基）

### 2.1 从 one-hot 说起

最朴素的做法是 one-hot：词表里第 3 个词就表示成 `[0,0,1,0,...]`。问题很明显：

- 词表 5 万个词，每个词就是个 5 万维的稀疏向量——**维度爆炸**
- "猫"和"狗"的 one-hot 向量距离一样远——**看不出语义相似**

### 2.2 词嵌入的思路

**把每个词映射成一个稠密的低维向量**（比如 128 维），让**语义相近的词，向量也相近**：

$$\text{猫} \to [0.21, -0.08, 0.97, \dots]$$
$$\text{狗} \to [0.19, -0.11, 0.93, \dots]$$

- 猫和狗的向量非常接近（都是宠物）
- 猫和汽车的向量差很远

```python
import torch
import torch.nn as nn

# 词表大小 10000，每个词用 128 维向量表示
embedding = nn.Embedding(num_embeddings=10000, embedding_dim=128)

ids = torch.tensor([[12, 45, 78]])       # 一句话：3 个词的编号
vectors = embedding(ids)
print(vectors.shape)                      # [1, 3, 128]
```

> 🔥 **这一步的意义**：文本 → 向量之后，"找相似的句子"就变成了"算向量的距离"。
>
> 这就是 **RAG（检索增强生成）** 的底层原理：文档 → 切成块 → 每块算一个向量（embedding）→ 存进向量库 → 用户提问时也转成向量 → 找最相似的块喂给大模型。**你现在学的 Embedding，就是之后 RAG 项目的第一块砖。**

## 三、初识：RNN——带"记忆"的网络

### 3.1 为什么全连接和 CNN 不行

- 全连接：每次输入独立处理，**没有记忆**——读到第 5 个词时，已经忘了第 1 个词
- CNN：擅长局部特征，但没法自然表达"前后依赖"

### 3.2 RNN 的思路：把上一步的"记忆"传下去

RNN 在每个时间步做同一件事：

$$h_t = \tanh(W_x x_t + W_h h_{t-1} + b)$$

- $x_t$：当前词（的向量）
- $h_{t-1}$：**上一步的隐藏状态**（记忆）
- $h_t$：当前步的隐藏状态，继续往后传

也就是：**读每个词时，都带着"前面读到的所有内容的摘要"**。

```python
rnn = nn.RNN(input_size=128, hidden_size=256, num_layers=1, batch_first=True)

x = torch.randn(16, 10, 128)      # (batch, 序列长度 10 个词, 词向量维度 128)
out, h_n = rnn(x)
print(out.shape)                   # [16, 10, 256] 每个时间步的输出
print(h_n.shape)                   # [1, 16, 256] 最后一步的隐藏状态（记忆摘要）
```

### 3.3 RNN 的毛病：记不住太久

理论上 RNN 能记住任意长的历史。实际上，序列一长，梯度在反向传播时层层连乘，容易**梯度消失**——读到第 50 个词时，第 1 个词的影响已经消失殆尽。

解决方案：**LSTM / GRU**（门控循环单元）。

| 模型 | 核心改进 |
|---|---|
| **LSTM** | 加"遗忘门/输入门/输出门"，决定"记什么、忘什么" |
| **GRU** | LSTM 的简化版（重置门 + 更新门），参数更少、训练更快 |

```python
lstm = nn.LSTM(input_size=128, hidden_size=256, batch_first=True)
gru  = nn.GRU(input_size=128, hidden_size=256, batch_first=True)
```

## 四、运用：周杰伦歌词生成

这是本模块最有意思的案例：让模型"学会"周杰伦的歌词风格，自己往下写。

### 4.1 任务转换：生成 = 不断预测下一个字

做法（字符级语言模型）：

1. 把歌词拆成一个个字，建成字表
2. 训练：给模型一段字"从前从前有个人爱你很久"，让它预测**下一个字**
3. 生成：给一个开头，让模型预测下一个字 → 拼上去 → 再预测 → 循环

> 🔥 **这里悄悄埋了个大伏笔**：GPT 系列大模型的训练目标，本质上也是**"预测下一个 token"**。你现在写的这个歌词生成，就是大模型训练方式的缩小版。

### 4.2 关键代码骨架

```python
import torch
import torch.nn as nn

class LyricsModel(nn.Module):
    def __init__(self, vocab_size, embed_dim=128, hidden_size=256):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim)
        self.rnn = nn.LSTM(embed_dim, hidden_size, batch_first=True)
        self.fc = nn.Linear(hidden_size, vocab_size)   # 输出每个字的概率

    def forward(self, x, hidden=None):
        x = self.embedding(x)                  # 字编号 → 词向量
        out, hidden = self.rnn(x, hidden)      # 记忆上下文
        logits = self.fc(out)                  # 每个时间步预测下一个字
        return logits, hidden

# 训练：输入 "从前从前"，标签 "从前从前" 向右移一位
# 生成：给开头 → 逐字预测 → 拼接到序列 → 继续预测
```

### 4.3 生成效果好坏看什么

| 现象 | 说明 |
|---|---|
| 生成的是"乱码字" | 训练不够 / 学习率问题 |
| 通顺但没风格 | 数据量太小，模型没学会风格 |
| 有周董味儿但偶尔跑偏 | 正常，字符级小模型的天花板 |

> 这个案例的重点不是"生成得多好"，而是理解**自回归生成**的机制：每次预测一个，喂回去，再预测下一个。

## 五、总结

### 5.1 要点回顾

1. 文本处理两步走：**词嵌入**（词 → 向量）+ **RNN**（处理顺序）
2. **Embedding**：把词映射成稠密向量，语义相近的词向量也相近——**RAG 向量检索的地基**
3. RNN 靠**隐藏状态在时间步之间传递**来记住上下文
4. RNN 的长序列问题（梯度消失）→ **LSTM / GRU** 用门控机制缓解
5. 歌词生成 = **自回归**：预测下一个字 → 拼回输入 → 继续预测——这正是大模型的训练/生成方式

### 5.2 自测清单

<details>
<summary>Q1：词嵌入相比 one-hot 的优势？</summary>

维度低（稠密向量）、能表达语义相似性（相近词距离近）、可学习；one-hot 维度爆炸且无法表达相似度。
</details>

<details>
<summary>Q2：RNN 凭什么能"记住"上下文？</summary>

隐藏状态 h 在时间步之间传递，每一步都融合了当前输入和历史信息。
</details>

<details>
<summary>Q3：RNN 有什么问题？LSTM 怎么解决？</summary>

长序列梯度消失/爆炸，难以捕捉长距离依赖；LSTM 用输入门、遗忘门、输出门控制信息的写入、保留与输出，缓解长依赖问题。
</details>

<details>
<summary>Q4：为什么说词嵌入和 RAG 有关？</summary>

RAG 把文档块编码成向量存进向量库，检索时用问题向量找最相似的文档向量——用的就是 embedding 这套"文本→向量"的技术。
</details>

### 5.3 面试视角（🔥 词嵌入 / 📌 RNN）

| 面试问法 | 答题要点 |
|---|---|
| 什么是词嵌入？ | 把离散的词映射为稠密向量，语义相近则向量距离近；可预训练（Word2Vec/GloVe）也可端到端学 |
| RNN 的原理？ | 隐藏状态沿时间步传递，每一步融合当前输入与历史信息 |
| RNN 的缺点？ | 长序列梯度消失/爆炸、无法并行（时间步串行） |
| LSTM 和 GRU 的区别？ | LSTM 三门（输入/遗忘/输出），GRU 两门（重置/更新），GRU 参数更少更快 |
| 为什么后来被 Transformer 取代？ | 注意力机制可并行、能建模任意距离依赖，训练效率高得多 |
