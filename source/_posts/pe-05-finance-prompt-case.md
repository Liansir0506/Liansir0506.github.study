## 一、初识：为什么拿金融文本练手

金融文本有三个特点，让它成为 Prompt 工程的"试金石"：

| 特点 | 挑战 |
|---|---|
| **术语密集** | "回购""减持""可转债"——模型得懂行话 |
| **表述严谨** | 差一个字意思就反了（"拟增持" vs "拟减持"） |
| **结果要能用** | 分类结果要进风控系统，抽取结果要进数据库——**必须结构化** |

三类典型任务：

```text
① 文本分类：这条公告是利好还是利空？
② 信息抽取：从公告里抽公司、事件、金额 → JSON
③ 相似度判断：这两条新闻说的是同一件事吗？
```

## 二、运用：任务一 · 金融文本分类

### 2.1 Prompt 设计

```python
messages = [
    {"role": "system", "content": """你是一名资深金融分析师。
判断给定公告对股价的影响方向，只输出以下三个标签之一：利好 / 利空 / 中性。
判断依据：
- 回购、增持、业绩预增 → 利好
- 减持、质押爆仓、业绩预亏 → 利空
- 常规披露、人事变动（非核心） → 中性"""},

    # Few-shot：给两个典型示例
    {"role": "user", "content": "公司拟回购不超过5亿元股份用于员工持股计划"},
    {"role": "assistant", "content": "利好"},
    {"role": "user", "content": "控股股东计划减持不超过2%股份"},
    {"role": "assistant", "content": "利空"},

    {"role": "user", "content": "【待分类公告】"}
]
```

### 2.2 设计要点

| 要点 | 说明 |
|---|---|
| **标签封闭** | 明确只有三个标签，别让模型自由发挥 |
| **判断依据** | 给出规则，减少主观性（模型按你的标准判，而不是它的标准） |
| **Few-shot 覆盖** | 至少给"利好/利空/中性"各一个示例 |
| **温度调低** | `temperature=0`，分类任务要稳定不要创意 |

## 三、运用：任务二 · 金融文本信息抽取

这是企业里最常用的场景：把非结构化的公告变成数据库里的字段。

### 3.1 Prompt 设计（结构化输出）

```python
prompt = """
从以下公告中抽取信息，严格按 JSON 输出（不要输出任何解释）：

{
  "company": "公司名称（没有则 null）",
  "event_type": "回购/减持/并购/重组/业绩预告/其他",
  "amount": "涉及金额（如 5亿元；没有则 null）",
  "date": "日期（YYYY-MM-DD；没有则 null）",
  "sentiment": "利好/利空/中性"
}

公告原文：
{text}
"""
```

### 3.2 优化版的两个技巧（对应代码里的"优化版"）

**技巧一：先让模型"想"，再让它"吐 JSON"**

```python
prompt = """
第一步：先分析公告里的关键要素（公司、事件、金额、日期）。
第二步：按下面的 JSON 格式输出结果，只输出 JSON。

【分析】
...
【JSON】
{...}
"""
```

**技巧二：字段缺失时的处理规范**

| 情况 | 正确做法 | 错误做法 |
|---|---|---|
| 公告没写金额 | `"amount": null` | 编一个数字 |
| 公司名不完整 | 提取原文中的简称 | 猜全称 |

> ⚠️ **抽取任务最大的坑是"模型编数据"**。Prompt 里必须明确："原文没有的信息一律填 null，禁止推测。"

### 3.3 工程侧校验（Prompt 之外）

```python
import json

def extract(text):
    raw = call_model(prompt.format(text=text))
    try:
        data = json.loads(raw)
    except json.JSONDecodeError:
        return {"error": "parse_failed", "raw": raw}

    # 字段校验：金额格式、枚举值合法性
    if data.get("event_type") not in {"回购", "减持", "并购", "重组", "业绩预告", "其他"}:
        data["event_type"] = "其他"
    return data
```

> 📌 记住：**Prompt 负责"尽量对"，代码负责"拦住错"**。两条腿走路。

## 四、运用：任务三 · 文本相似度判断

### 4.1 两种做法

| 方案 | 做法 | 特点 |
|---|---|---|
| **大模型判断** | 把两段文本都给模型，问"是否讲同一件事" | 灵活，能理解语义；慢、贵、不稳定 |
| **Embedding 余弦相似度** | 两段文本转向量，算余弦值 | 快、便宜、可批量；需要阈值调参 |

### 4.2 Prompt 方案

```python
prompt = f"""
判断以下两条金融新闻是否在讲同一件事（同一公司 + 同一事件）。
只输出：相同 / 相关 / 不同

新闻A：{text_a}
新闻B：{text_b}
"""
```

### 4.3 Embedding 方案（更适合批量）

```python
from sklearn.metrics.pairwise import cosine_similarity

vec_a = get_embedding(text_a)     # 用 BERT 类模型编码
vec_b = get_embedding(text_b)
score = cosine_similarity([vec_a], [vec_b])[0][0]
print(score)      # 0~1，一般 > 0.85 视为高度相似（阈值需按业务调）
```

> 💡 怎么选：
> - **数据量大、要实时** → embedding（向量库检索就是这么干的，也是 RAG 的基础）
> - **判断标准复杂、需要解释** → 大模型

## 五、初识：三条实战经验（踩过坑才懂）

### 5.1 输出格式：宁可"傻"，也要"稳"

- 用固定枚举（利好/利空/中性），不要让模型自由描述
- JSON 字段名和类型写死
- 加一句"只输出 JSON，不要任何解释"——**这一句能挡住 80% 的解析错误**

### 5.2 少样本示例：质量 > 数量

- 2~3 个高质量示例（覆盖典型情况）> 10 个随便找的例子
- 示例的输出格式必须和期望的最终格式一模一样
- 示例里别放"边界模糊"的案例（会把模型带偏）

### 5.3 结果校验：模型输出不可全信

| 校验点 | 做法 |
|---|---|
| 格式 | JSON 解析 + schema 校验 |
| 枚举值 | 标签必须在你定义的集合里 |
| 数值合理性 | 金额是否在合理区间 |
| 抽样人工复核 | 每天抽 5% 检查（尤其上线初期） |

> 🔥 一句话总结这三条：**Prompt 决定上限，工程校验决定下限**。企业级应用永远是"Prompt + 代码校验 + 人工兜底"三层。

## 六、总结

### 6.1 要点回顾

1. 金融文本的挑战：术语密、表述严谨、结果必须结构化
2. **分类任务**：标签封闭 + 判断依据 + Few-shot 覆盖各类 + 低温
3. **抽取任务**：JSON 模板 + 缺失填 null + "禁止推测" + 工程侧校验
4. **相似度任务**：大模型判断（灵活）vs Embedding 余弦（快、批量，RAG 基础）
5. 三条经验：**输出格式要稳、示例要精、结果必须校验**

### 6.2 自测清单

<details>
<summary>Q1：抽取任务怎么防止模型编造字段？</summary>

Prompt 明确"原文没有的信息填 null，禁止推测"；输出后用代码校验字段类型和枚举值；关键字段抽样人工复核。
</details>

<details>
<summary>Q2：分类任务的 temperature 为什么调低？</summary>

分类需要稳定、可复现的结果；高温会引入随机性，同一输入可能给出不同标签。
</details>

<details>
<summary>Q3：相似度判断，大模型和 embedding 怎么选？</summary>

大数据量、要求快和便宜 → embedding + 阈值；标准复杂、需要语义解释 → 大模型判断。
</details>

<details>
<summary>Q4：企业级 Prompt 应用为什么要"三层保障"？</summary>

Prompt 保证效果上限，代码校验拦截格式/枚举错误，人工复核兜底边界情况——单靠 Prompt 无法保证生产可靠性。
</details>

### 6.3 面试视角（📌）

| 面试问法 | 答题要点 |
|---|---|
| 用大模型做信息抽取怎么保证准确？ | 结构化模板 + null 规则 + 少样本 + 代码校验 + 抽样复核 |
| 大模型分类和传统分类模型怎么选？ | 数据少/标签会变 → 大模型（免训练）；数据多/要求极致稳定 → 微调小模型 |
| 文本相似度有哪些方案？ | 字面（编辑距离/Jaccard）、语义（embedding 余弦）、大模型判断 |
| Prompt 应用怎么上线？ | 灰度 + 抽样评估 + 兜底策略 + 监控解析失败率 |
