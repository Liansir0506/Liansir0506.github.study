## 一、初识：私人助理的比喻

你雇了一位助理，任务："帮我安排下周去上海的出差。"

| | 普通助手（基础 LLM） | 优秀助理（Agent） |
|---|---|---|
| 回答 | "建议乘坐高铁 G101，约 4.5 小时" | 真的去查票、查天气、订酒店、排日程 |
| 依据 | 训练数据里的知识 | 实时调用外部系统 |
| 是否办成 | ❌ 只是建议 | ✅ 交付可执行的方案 |

Agent 做的五件事：

```text
① 理解目标：出差 = 交通 + 住宿 + 日程
② 主动查询：调订票系统 / 天气 API / 酒店系统
③ 规划步骤：先订票（锁日期）→ 再订酒店（靠近会议地点）→ 出行程
④ 检查修正：发现会议下午、高铁到太晚 → 改签早班
⑤ 交付结果：一份完整的出差方案
```

> 🔥 官方定义可以背下来：
> **Agent = 大模型（大脑）+ 工具使用（手脚）+ 规划能力（策略）+ 记忆（经验）**

## 二、初识：Agent vs 普通 LLM

| 维度 | 普通 LLM | Agent |
|---|---|---|
| **能力边界** | 只能用训练数据 | 调外部工具获取实时信息、操作外部系统 |
| **任务处理** | 一问一答、被动响应 | **主动拆解、规划、逐步执行** |
| **错误处理** | 错了也不知道 | 自我检查、发现后修正 |
| **多步任务** | 无法自主完成 | 多工具、多次调用、端到端 |
| **类比** | 博学但不出门的顾问 | 能办事的助理 |

### 2.1 一个具体例子

用户："帮我查上海明天的天气，如果下雨就取消户外行程并改订室内活动。"

- **普通 LLM**：只能答"我无法查询实时天气"，或者**编一个天气**（幻觉）
- **Agent**：
  1. 调天气工具 → 发现"中雨"
  2. 判断需要取消户外
  3. 调日历工具取消户外行程
  4. 调活动搜索工具找室内活动
  5. 返回完整调整方案

## 三、初识：什么是 Agentic（重要概念）

**Agentic 是一个形容词**——描述系统"像 Agent 的程度"。**它不是二值（是/不是），而是连续谱。**

| Agentic 程度 | 系统表现 | 生活类比 |
|---|---|---|
| **低** | 按预设规则回答 | 自动应答客服（关键词回复固定话术） |
| **中** | 能调工具完成单步任务，不会自主规划 | 餐厅服务员（能下单，不会主动推荐搭配） |
| **高** | 自主规划、多工具、检查修正、多 Agent 协作 | 资深私人助理（安排整趟出差，遇问题主动调整） |

> 📌 面试时用这个词会显得很专业："我们这个项目是**高 Agentic** 系统——具备规划、工具编排与自我修正能力。"

### 3.1 Agentic 的三个标志（Lilian Weng 的经典总结）

OpenAI AI 主管 Lilian Weng 在《LLM Powered Autonomous Agents》中提出，具备 Agentic 特性的系统会：

| 标志 | 表现 |
|---|---|
| **主动思考** | 不傻等指令，自己判断下一步 |
| **自我修正** | 发现自己错了，自己去改 |
| **主动获取信息** | 意识到信息不足，主动调用工具 |
| **任务拆解** | 复杂任务自己拆成小步骤 |

这篇博客是智能体领域的里程碑，系统梳理了 **规划（Planning）、记忆（Memory）、工具使用（Tool Use）** 三大组件。

## 四、初识：五种 Agent 模式

| 模式 | 核心思想 | 例子 |
|---|---|---|
| **① 工具使用（Tool Use）** | 调外部工具扩展能力 | 查天气、查数据库 |
| **② 规划（Planning）** | 先拆解任务、再逐步执行 | 先订票后订酒店 |
| **③ 反思（Reflection）** | 检查自己的输出、发现错误再改 | 生成行程后自查时间冲突 |
| **④ 多 Agent 协作** | 多个专业 Agent 分工 | 天气 Agent + 酒店 Agent（→ A2A） |
| **⑤ 人机协同（HITL）** | 关键节点请人确认 | 付款前请用户确认 |

> 这些模式与 **ReAct** 一脉相承：ReAct 的"Thought → Action → Observation"循环，就是"工具使用 + 反思"的最小实现（pe-04）。

### 4.1 本项目用到哪几种

| 模式 | 在本项目中的体现 |
|---|---|
| 工具使用 | MCP 暴露的天气/地图/搜索/航班工具 |
| 规划 | 主 Agent 拆解"规划旅行"为多个子任务 |
| 多 Agent 协作 | 主 Agent 通过 A2A 调各专业 Agent |
| 反思 | 行程冲突时重新规划 |
| 人机协同 | 订票/支付前确认 |

## 五、初识：为什么 Agent 需要"记忆"

没有记忆的 Agent：

```text
用户：帮我订明天去成都的票
Agent：（查票）→ 有 3 个航班
用户：第二个
Agent：什么第二个？（忘了上一轮）
```

记忆的三层：

| 层 | 内容 | 技术 |
|---|---|---|
| **短期记忆** | 当前对话上下文 | messages 历史 |
| **长期记忆** | 用户偏好、历史任务 | 向量库检索 / 数据库 |
| **工作记忆** | 当前任务的中间结果 | 上下文变量 / 草稿区 |

> 📌 在 Agent 里，记忆不只是"聊天记录"，还包括"任务执行到哪一步了"——这也是 A2A 要管理 Task 状态的原因（下一篇）。

## 六、总结

### 6.1 要点回顾

1. **Agent = 大模型 + 工具 + 规划 + 记忆**
2. 与 LLM 的区别：主动拆解任务、调工具、自我检查、完成端到端多步任务
3. **Agentic 是连续谱**：低（规则回复）→ 中（单步工具）→ 高（规划+多 Agent）
4. 五种模式：**工具使用 / 规划 / 反思 / 多 Agent / 人机协同**
5. 记忆三层：短期（对话）、长期（偏好/历史）、工作（任务中间态）

### 6.2 自测清单

<details>
<summary>Q1：Agent 的四个组成部分？</summary>

大模型（决策与生成）、工具（外部能力）、规划（任务拆解与执行策略）、记忆（上下文与历史）。
</details>

<details>
<summary>Q2：Agentic 是什么？为什么说是连续谱？</summary>

描述系统"像 Agent 的程度"——从规则回复（低）到单步工具（中）到自主规划与多 Agent 协作（高），不是非黑即白。
</details>

<details>
<summary>Q3：Agent 和 ReAct 的关系？</summary>

ReAct 是 Agent 的一种基础运行范式（Thought→Action→Observation 循环）；Agent 是更完整的系统，还包含规划、记忆、反思、多 Agent 协作等能力。
</details>

<details>
<summary>Q4：Agent 的记忆分几层？</summary>

短期（对话上下文）、长期（用户偏好/历史，常用向量库）、工作记忆（当前任务中间状态）。
</details>

### 6.3 面试视角（🔥🔥）

| 面试问法 | 答题要点 |
|---|---|
| 什么是 Agent？和 LLM 区别？ | LLM+工具+规划+记忆；能主动拆解、执行、修正，完成端到端任务 |
| Agentic 是什么？ | 系统自主性的连续谱；高 Agentic = 规划+工具+反思+协作 |
| Agent 的核心组件？ | Planning / Memory / Tool Use（Lilian Weng 框架） |
| Agent 有哪些模式？ | 工具使用、规划、反思、多 Agent、人机协同 |
| Agent 落地的难点？ | 工具调用的稳定性、长任务规划、状态管理、成本与延迟、评测 |
